# AITY VIP 项目 AI-Coding 交互规则

**版本**: v1.0.0
**创建日期**: 2026-02-27
**适用范围**: 本项目所有 AI 辅助开发工作

---

## 一、自动执行原则

AI 在执行任务时应**自动处理**以下事项，无需用户额外提醒：

### 1.1 服务启动
在执行测试或需要运行环境的任务时，AI 应自动：
- 启动后端服务 (`npm run dev`)
- 启动 H5 前端服务 (`npm run dev:h5`)
- 编译小程序 (`npm run build:mp-weixin`)

### 1.2 代码提交
任务完成后，AI 应自动：
- 检查 git 状态
- 添加修改文件到暂存区
- 创建规范的 commit 信息
- 提交代码（除非用户明确要求不提交）

### 1.3 文档更新
功能修改完成后，AI 应自动：
- 更新相关文档
- 更新版本号（如适用）
- 更新测试清单（如适用）

## 二、Git 提交规范

### 2.1 Commit 消息格式
```
<type>(<scope>): <subject>

<body>

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
```

### 2.2 Type 类型
| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档更新 |
| `style` | 代码格式调整 |
| `refactor` | 代码重构 |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具相关 |

### 2.3 自动提交时机
- 功能开发完成后
- Bug 修复完成后
- 代码重构完成后
- 用户明确要求提交时

## 三、任务执行流程

### 3.1 标准流程
```
1. 接收任务 → 创建 Todo 列表
2. 分析需求 → 确认理解正确
3. 启动服务 → 后端 + H5 + 小程序编译
4. 执行任务 → 按步骤完成
5. 自测验证 → 确保功能正常
6. 更新文档 → 记录修改内容
7. 提交代码 → Git commit
8. 汇报结果 → 总结完成情况
```

### 3.2 多任务并行
- 使用多 Agent 并行处理独立任务
- 任务完成后汇总结果
- 最后统一提交代码

## 四、测试规范

### 4.1 测试前准备
AI 应自动完成：
- [ ] 检查后端服务是否运行
- [ ] 检查 H5 服务是否运行
- [ ] 检查小程序是否编译完成
- [ ] 检查数据库连接是否正常

### 4.2 测试类型
| 类型 | 工具 | 说明 |
|------|------|------|
| API 测试 | curl / Playwright | 后端接口测试 |
| H5 测试 | Playwright | 浏览器自动化 |
| 小程序测试 | 微信开发者工具 | 手动测试 |
| 真机测试 | ADB | Android 设备测试 |

---

## 五、文件修改规范

### 5.1 修改文件前
- 先读取文件内容，了解当前实现
- 确认修改不会破坏现有功能
- 保持代码风格一致

### 5.2 新增文件
- 遵循项目目录结构
- 使用统一的命名规范
- 添加必要的注释
