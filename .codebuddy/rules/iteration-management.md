> **最后更新**: 2026-05-02  
> **适用范围**: AITY_VIP 项目所有迭代开发

## 🔧 使用流程（强制执行）

### 开始新迭代时

```bash
# 1. 创建迭代分支（重大功能）
cd d:\your-mcp-proxy\AITY_VIP
git checkout develop
git pull origin develop
git checkout -b feature/迭代名称

# 2. 初始化3个核心文件
# - 复制模板到对应文件
# - 填写迭代基本信息

# 3. 通知用户
"已创建迭代 v1.7.x 的任务计划，请查看 docs/08-项目规划/iterations/task-plan.md"
```

### 每次开始工作时

```markdown
## ✅ 必须执行的检查清单

- [ ] 1. 重读 `task-plan.md` - 了解当前任务和优先级
- [ ] 2. 重读 `progress.md` - 了解上次会话进展和待办事项
- [ ] 3. 检查 `findings.md` - 查看是否有相关调研结论
- [ ] 4. 确认用户是否在等待某个任务的结果
```

### 工作过程中

```markdown
## ✅ 必须记录的内容

- [ ] 1. 遇到问题时 - 立即记录到 `progress.md` 的"遇到的问题"部分
- [ ] 2. 做出决策时 - 记录决策原因到 `findings.md`
- [ ] 3. 完成某个步骤时 - 更新 `task-plan.md` 的进度表
- [ ] 4. 发现新的待办事项时 - 添加到 `task-plan.md`
```

### 每次会话结束后

```bash
# 1. 更新 progress.md
# - 记录本次工作内容
# - 记录遇到的问题和解决方案
# - 记录代码改动
# - 记录测试结果
# - 记录下次会话计划

# 2. 更新 task-plan.md
# - 更新任务完成度
# - 更新迭代进度表

# 3. 如有新调研，更新 findings.md

# 4. 提交 Git（如果性能好）
git add docs/08-项目规划/iterations/
git commit -m "docs: 更新迭代记录 - 会话MM-DD"

# 5. 通知用户
"本次会话已完成，进度已记录到 progress.md，请查看"
```

## 📝 迭代记录规范（必须！）

### 记录位置
`docs/08-项目规划/iteration-records.md`

### 记录格式
```markdown
### [版本号] 迭代标题
- **日期**: YYYY-MM-DD
- **Git Commit**: <commit-hash>
- **修改文件**:
  - 文件1: 修改内容
  - 文件2: 修改内容
- **测试情况**:
  - 后端: ✅/❌
  - 前端: ✅/❌
- **已知问题**: <如有>
- **回退命令**:
  ```bash
  git reset --hard <commit-hash>
  ```
```

### 每次迭代后必须
1. ✅ 更新 `docs/08-项目规划/iteration-records.md`
2. ✅ 提交 Git (带详细提交信息)
3. ✅ Push 到远程仓库

---

## 🎯 核心要点（AI 必须记住）

1. **文件维护**
   - 每次会话前必须重读3个核心文件
   - 每次会话后必须更新3个核心文件
   - 用文件系统做外部记忆，解决跨会话AI遗忘上下文的问题

2. **迭代流程**
   - 修改代码 → 本地测试 → 用户验收 → 提交Git → 询问部署
   - 每个阶段都要更新对应的文档

3. **提交规范**
   - 必须写详细的提交信息（符合 Conventional Commits 规范）
   - 必须更新 `docs/08-项目规划/iteration-records.md`
   - 提交信息要说明"修改原因"而非仅描述修改内容

4. **部署规范**
   - 只有用户确认后才能部署生产环境
   - 严禁跳过验收流程

---

## 🚫 AI 禁止执行的操作

1. ❌ **未经用户确认就部署生产环境**
2. ❌ **跳过验收流程**
3. ❌ **在开发环境连接生产数据库**
4. ❌ **不记录迭代内容就提交 Git**
5. ❌ **不维护3个核心文件就开始工作**
