## 🔄 快速切换

### 方式1: 使用环境变量（推荐）

#### 切换到测试数据库

**Windows (CMD)**
```cmd
set DB_ENV=test
npm run start
```

**Windows (PowerShell)**
```powershell
$env:DB_ENV="test"
npm run start
```

**Linux/Mac**
```bash
export DB_ENV=test
npm run start
```

#### 切换到生产数据库

**Windows (CMD)**
```cmd
set DB_ENV=production
npm run start
```

**Windows (PowerShell)**
```powershell
$env:DB_ENV="production"
npm run start
```

**Linux/Mac**
```bash
export DB_ENV=production
npm run start
```

### 方式2: 修改 .env 文件

**文件**: `backend/.env`

```bash
# ============================================
# 数据库配置
# ============================================

# 服务器配置（固定）
DB_HOST=124.221.119.134
DB_PORT=3306
DB_USER=fl
DB_PASSWORD=fl10b312

# 环境选择（修改这里切换数据库）
DB_ENV=test          # test=测试数据库, production=生产数据库

# 或直接指定数据库名称（优先级更高）
# DB_NAME=投研图灵室_test    # 取消注释可强制使用指定数据库
```

**切换步骤**:
1. 打开 `backend/.env`
2. 修改 `DB_ENV=test` 或 `DB_ENV=production`
3. 重启后端服务

## 📖 详细说明

### 配置文件逻辑

**文件**: `backend/src/config/db.js`

```javascript
// 自动选择数据库的逻辑
const getDatabaseName = () => {
  // 1. 如果 .env 中明确指定了 DB_NAME，优先使用
  if (process.env.DB_NAME) {
    return process.env.DB_NAME;
  }

  // 2. 否则根据 DB_ENV 自动选择
  if (DB_ENV === 'production') {
    return '投研图灵室';      // 生产数据库
  } else {
    return '投研图灵室_test'; // 测试数据库（默认）
  }
};
```

### 优先级规则

```
DB_NAME（明确指定）  >  DB_ENV（环境变量）  >  默认值

示例：
❌ DB_NAME=投研图灵室       → 使用"投研图灵室"（忽略DB_ENV）
❌ DB_ENV=production        → 使用"投研图灵室"
✅ 两者都不设置              → 使用"投研图灵室_test"（默认测试）
```

```bash
# 1. 导出测试数据库（包含数据）
mysqldump -h 124.221.119.134 -u fl -p'fl10b312' \
  投研图灵室_test > test_db_backup.sql

# 2. 导入到生产数据库

  投研图灵室 < test_db_backup.sql

mysql -h 124.221.119.134 -u fl -p'fl10b312' \
  -e "USE 投研图灵室; SELECT COUNT(*) FROM users;"
```

```bash
# 1. 导出测试数据库结构（不含数据）

  --no-data 投研图灵室_test > schema.sql

mysql -h 124.221.119.134 -u fl -p'fl10b312' \
  投研图灵室 < schema.sql
```


## 💾 备份与恢复

### 备份脚本

**文件**: `backend/scripts/backup-database.sh`

```bash
#!/bin/bash

# 配置
DB_HOST="124.221.119.134"
DB_USER="fl"
DB_PASS="fl10b312"
BACKUP_DIR="./backups"
DATE=$(date +%Y%m%d_%H%M%S)

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份测试数据库
echo "🟢 备份测试数据库..."
mysqldump -h $DB_HOST -u $DB_USER -p$DB_PASS \
  投研图灵室_test > $BACKUP_DIR/test_db_$DATE.sql

# 备份生产数据库
echo "🔴 备份生产数据库..."
mysqldump -h $DB_HOST -u $DB_USER -p$DB_PASS \
  投研图灵室 > $BACKUP_DIR/prod_db_$DATE.sql

echo "✅ 备份完成！"
echo "   测试数据库: $BACKUP_DIR/test_db_$DATE.sql"
echo "   生产数据库: $BACKUP_DIR/prod_db_$DATE.sql"
```

**使用方法**:
```bash
chmod +x backend/scripts/backup-database.sh
cd backend
./scripts/backup-database.sh
```

### 恢复脚本

**文件**: `backend/scripts/restore-database.sh`

```bash
#!/bin/bash

# 参数检查
if [ -z "$1" ]; then
  echo "用法: ./restore-database.sh <backup_file.sql> [test|production]"
  echo "示例: ./restore-database.sh backups/test_db_20260210.sql test"
  exit 1
fi

BACKUP_FILE=$1
DB_ENV=${2:-test}
DB_NAME="投研图灵室_test"

if [ "$DB_ENV" = "production" ]; then
  DB_NAME="投研图灵室"
  echo "⚠️  警告: 即将恢复到生产数据库！"
  read -p "确认继续? (yes/no): " confirm
  if [ "$confirm" != "yes" ]; then
    echo "已取消"
    exit 1
  fi
fi

# 恢复数据库
echo "📥 恢复数据库: $DB_NAME"
mysql -h 124.221.119.134 -u fl -p'fl10b312' \
  $DB_NAME < $BACKUP_FILE

echo "✅ 恢复完成！"
```

## 🔒 安全建议

### 1. 权限分离

**开发环境**: 测试数据库
- ✅ 可以删除、修改数据
- ✅ 可以重置表结构
- ✅ 适合测试和调试

**生产环境**: 生产数据库
- ❌ 禁止直接修改数据
- ❌ 禁止删除操作
- ✅ 只能通过应用操作

### 2. 定期备份

**建议备份频率**:
- 测试数据库: 每周一次
- 生产数据库: 每天一次

**自动备份脚本**: 添加到 crontab

```bash
# 每天凌晨2点备份
0 2 * * * /path/to/backend/scripts/backup-database.sh
```

### 3. 敏感数据保护

**生产数据库特殊处理**:
- 用户密码：加密存储
- 敏感信息：脱敏显示
- 操作日志：完整记录

## ❓ 常见问题

### Q1: 如何确认当前使用的是哪个数据库？

**A**: 查看后端启动日志

```
✅ 数据库连接成功
   环境: 🔴 生产环境  ← 这里会显示
   数据库: 投研图灵室  ← 这里会显示数据库名
```

### Q2: 测试和生产数据库可以同时存在吗？

**A**: 可以！它们在同一个MySQL服务器上：

```
MySQL服务器
├── 投研图灵室_test    ← 测试环境使用
└── 投研图灵室         ← 生产环境使用
```

只需通过 `DB_ENV` 环境变量切换即可。

### Q3: 开发时应该用哪个数据库？

**A**: 日常开发使用**测试数据库**：

```bash
DB_ENV=test  # 默认配置
```

原因：
- ✅ 不会影响生产数据
- ✅ 可以随意测试
- ✅ 修改数据无风险

### Q4: 什么时候切换到生产数据库？

**A**: 仅在以下场景：

1. **正式发布上线**
   ```bash
   DB_ENV=production
   npm run start
   ```

2. **验证生产环境问题**
   ```bash
   DB_ENV=production
   npm run start
   ```

3. **生产数据维护**
   - 需要谨慎操作
   - 建议先备份数据

### Q5: 如何在生产环境测试新功能？

**A**: 推荐流程：

1. **在测试数据库开发和测试**
   ```bash
   DB_ENV=test
   npm run start
   ```

2. **功能稳定后，迁移到生产数据库**
   - 先备份生产数据库
   - 运行数据库迁移脚本
   - 验证功能

3. **切换到生产环境**
   ```bash
   DB_ENV=production
   npm run start
   ```
