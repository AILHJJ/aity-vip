## 测试框架

### DevBrowser核心API

```typescript
import { connect, waitForPageLoad } from "@/client.js";

// 连接浏览器
const client = await connect();
const page = await client.page("test-name");

// 使用AI快照
const snapshot = await client.getAISnapshot("test-name");
const btn = await client.selectSnapshotRef("test-name", "e30");
await btn.click();
```

### uni-app测试最佳实践

```typescript
// 问题1: 遮罩层拦截 - 使用 force
await locator.click({ force: true });

// 问题2: 组件选择器 - 使用AI快照
const element = await client.selectSnapshotRef("page", "e17");

// 问题3: 等待加载 - 使用waitForPageLoad
await waitForPageLoad(page);
```

## 测试策略

### 分层测试

```
┌─────────────────────────────────────┐
│  E2E测试 (DevBrowser + Playwright)  │ ← 完整业务流程
├─────────────────────────────────────┤
│     集成测试 (API测试)              │ ← 接口交互
├─────────────────────────────────────┤
│     单元测试 (Jest)                 │ ← 函数级测试
└─────────────────────────────────────┘
```

### 测试类型

| 测试类型 | 工具 | 覆盖范围 | 执行频率 |
|---------|------|----------|----------|
| **E2E测试** | DevBrowser, Playwright | 完整用户流程 | 每次提交 |
| **API测试** | Jest, Supertest | API接口 | 每次提交 |
| **单元测试** | Jest | 函数、组件 | 每次提交 |
| **性能测试** | Lighthouse | 页面性能 | 每周 |
| **安全测试** | OWASP ZAP | 安全漏洞 | 每月 |

## 测试流程

### 开发测试流程

```
1. 编写代码
   ↓
2. 编写测试用例
   ↓
3. 运行本地测试
   ↓
4. 提交代码 (自动触发CI测试)
   ↓
5. 代码审查
   ↓
6. 合并到主分支
   ↓
7. 部署到测试环境
   ↓
8. 执行E2E测试
   ↓
9. 性能测试
   ↓
10. 发布到生产环境
```

### Bug处理流程

```
1. 发现Bug
   ↓
2. 创建Bug报告
   ↓
3. 分配给开发人员
   ↓
4. 开发修复
   ↓
5. 提交修复和测试用例
   ↓
6. 验证测试
   ↓
7. 关闭Bug报告
```

## 测试报告

### 测试报告模板

测试报告应包含以下内容：

1. **测试概述**
   - 测试时间
   - 测试人员
   - 测试版本

2. **测试范围**
   - 功能模块
   - 测试用例数

3. **测试结果**
   - 通过用例数
   - 失败用例数
   - 缺陷列表

4. **测试结论**
   - 质量评估
   - 发布建议
