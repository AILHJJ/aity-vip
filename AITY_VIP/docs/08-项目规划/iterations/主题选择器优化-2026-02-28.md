## 一、需求背景

### 1.1 原有问题

用户在发布消息时选择 Markdown 主题样式存在以下交互问题：

| 问题 | 描述 |
|------|------|
| 发现性差 | 主题选择器隐藏在预览模式下，用户需要先点击"预览"才能看到 |
| 操作繁琐 | 编辑内容 -> 点击预览 -> 选择主题 -> 切回编辑，步骤过多 |
| 编辑预览分离 | 编辑区和主题选择区物理分离，心智负担重 |
| 无记忆功能 | 每次都需要重新选择主题，无法记住上次选择 |

### 1.2 用户反馈

> "是否可以更优化？编辑后选择样式还是默认记住上次的样式呢？是要点击预览才能看到效果吗？"

> "AI优化按钮是否也可以考虑放在同一行呢？"

> "主题颜色选择的时候如何交互呢，下拉项选择还是左右滑动？"

---

## 二、解决方案

### 2.1 设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 位置 | 内容编辑区下方 | 编辑完成后直接操作，流程自然 |
| 交互方式 | 下拉选择器 | 节省空间，符合用户习惯 |
| 预览方式 | 颜色块预览 | 直观展示主题色调，快速识别 |
| 记忆功能 | localStorage | 自动保存，下次自动恢复 |
| AI按钮 | 同行排列 | 相关功能集中，操作便捷 |

#### 3.1.2 脚本逻辑 (Script)

```javascript
// localStorage 键名
const THEME_KEY = 'last_selected_theme'

// 主题预览颜色计算
const currentThemePreviewColor = computed(() => {
  const theme = themeOptions.find(t => t.value === formData.value.theme)
  return theme ? theme.previewColor : 'linear-gradient(135deg, #667eea 0%, #764ba2 100%)'
})

// 主题变更处理（带记忆）
const handleThemePickerChange = (e) => {
  const index = e.detail.value
  formData.value.theme = themeOptions[index].value
  uni.setStorageSync(THEME_KEY, formData.value.theme)  // 保存到本地
}

// 恢复上次选择的主题
const restoreLastTheme = () => {
  const lastTheme = uni.getStorageSync(THEME_KEY)
  if (lastTheme) {
    formData.value.theme = lastTheme
  }
}

// onMounted 中调用
onMounted(() => {
  // ...
  restoreLastTheme()
  // ...
})
```
