## 三、存在的问题和报错

### 3.1 图片 404（环境数据不一致）
**表现**：消息详情页图片加载 404
```
Failed to load image http://localhost:3001/uploads/images/img-1776650457413-gfig2z0ehx.png
the server responded with a status of 404
```
**原因**：消息数据是从生产环境同步过来的，图片文件只存在于生产服务器，本地 `backend/uploads/images/` 没有这些文件。

**已处理**：前端已加图片加载失败占位图（🖼️ 图片加载失败 + 点击重试）。

**根治方案**：将生产服务器 `backend/uploads/images/` 目录同步到本地。

### 3.2 "互动交流"筛选无效（架构遗留问题）
**表现**：点击"互动交流"tab，筛选不到任何讨论。

**跟因**：`discussions` 表的 `status` ENUM 只有 `'pending'` 和 `'replied'`，没有 `'feedback'`。前端的 `value: 'feedback'` 发送到后端后，数据库中不存在对应状态。

| 筛选 | value | 后端 ENUM | 是否有数据 |
|------|-------|-----------|-----------|
| 互动交流 | `feedback` | ❌ 不存在 | ❌ |
| 待回复 | `pending` | ✅ | 取决于数据 |
| 已回复 | `replied` | ✅ | 取决于数据 |

**待修复**：
1. 后端 `Discussion.js` 的 status ENUM 增加 `'feedback'`
2. 数据库执行：`ALTER TABLE discussions MODIFY COLUMN status ENUM('pending','replied','feedback')...`
3. 前端双向互动页面（create-discussion 等）需支持发起"互动交流"类型的讨论

### 3.3 消息类型筛选无内容（数据问题）
**表现**：筛选"持仓/风险/点评/系统"时，消息列表为空。

**原因**：本地数据库中没有这些类型的消息数据，非代码问题。

### 3.4 图片上传问题
**表现**：部分图片上传后文件不存在于本地目录。

**可能原因**：上传请求可能发送到了生产服务器，或本地后端重启导致临时文件丢失。需排查上传 API 的 base_url 配置。
