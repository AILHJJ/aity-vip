# 目录整理执行清单

> 日期: 2026-05-02  
> 目标: 在不破坏当前可运行版本的前提下, 分批整理项目目录, 让后续迭代更清晰。  
> 原则: 先文档化、再分支化、再移动/删除; 不在当前脏工作区直接清理。

---

## 1. 目标结构

建议保留的顶层结构:

```text
AITY_VIP/
├── README.md
├── backend/                 # Node.js 后端服务
├── aity-uni-app-v2/          # uni-app H5/微信小程序主前端
├── docs/                    # 项目文档唯一入口
├── scripts/                 # 跨模块部署/运维脚本
├── tests/                   # 根级集成测试和端到端测试
├── ssl-certs/               # 证书说明和非敏感脚本
├── aity88.online_nginx/      # Nginx/证书资料, 需确认是否含敏感证书
└── .github/                 # CI/CD 配置
```

不建议继续作为顶层主目录:

| 路径 | 当前问题 | 建议 |
| --- | --- | --- |
| `frontend/` | 旧/新前端方向不清, 与 `aity-uni-app-v2/` 冲突 | 先确认用途; 若废弃, 归档到 `archive/legacy-frontend/`; 若保留, 改名为 `pc-web/` 并补 README |
| `backup/` | 历史备份未分类 | 迁移到 `docs/已归档文档/` 或外部备份目录 |
| 根目录散落报告/测试文件 | 入口噪声大 | 移入 `docs/已归档文档/修复报告/` 或删除 |
| `$null` | 异常文件 | 确认无用后删除 |

## 2. 分批执行方案

  - 目录整理执行清单

## 3. 文件去留规则

### 必须保留

- 当前运行代码: `backend/src`, `aity-uni-app-v2/src`
- 依赖和构建配置: `package.json`, `vite.config.js`, `ecosystem.config.js`
- 数据库迁移: `backend/migrations`
- 生产部署说明: `docs/04-部署指南`, `docs/05-运维手册`
- 最新需求和路线图: `docs/08-项目规划`

### 需要归档

- 历史修复报告
- 历史原型 HTML
- 旧需求草稿
- 旧测试报告
- 已完成迭代的中间文档

### 需要删除或移出 Git

- 明文证书和私钥
- 明文 token、密码、生产数据库备份
- 临时 zip、tar.gz
- Playwright 报告产物
- 构建产物 `dist/` 中可再生成内容
- 异常文件 `$null`, `l`

删除前必须确认:

1. 是否已经在服务器或外部备份中保存。
2. 是否还能通过构建或测试重新生成。
3. 是否被 README、脚本或代码引用。

## 4. 推荐执行顺序

1. 安全冻结和 token 轮换。
2. 创建清理分支。
3. 更新文档入口。
4. 清理敏感文件和构建产物。
5. 整理 `docs/`。
6. 整理 `aity-uni-app-v2/`。
7. 整理 `backend/`。
8. 跑冒烟测试。
9. 合并到 `develop`。
10. 从 `develop` 拉 `release/2026-05-baseline`。

---

## 5. 验收标准

- 根目录文件数量明显减少, 只保留入口和关键配置。
- `docs/README.md` 能解释所有主要目录用途。
- `README.md` 不再出现过期生产端口和旧活动分支。
- Git 工作区干净。
- `main`、`develop`、`release/*` 职责清楚。
- 新迭代可以从稳定分支拉出, 不依赖旧 `feature/iteration-1`。
