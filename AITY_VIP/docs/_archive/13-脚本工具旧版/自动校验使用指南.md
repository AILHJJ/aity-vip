# Git钩子 + Skill 快速使用指南

## 🎯 已创建的自动化工具

### 1. Git Pre-commit钩子 ✅

**位置**: `.git/hooks/pre-commit`
**功能**: 每次提交前自动校验文档质量
**触发条件**: `git commit` 时有Markdown文件变更

**使用方式**:
```bash
# 正常提交（自动运行校验）
git add docs/your-doc.md
git commit -m "docs: 更新文档"

# 跳过校验（不推荐）
git commit --no-verify -m "docs: 更新文档"
```

**输出示例**:
```
🔍 正在检查文档质量...

📄 检查以下文档：
  - docs/06-features/ai-assistant/README.md

🚀 运行文档校验工具...
✅ 文档质量检查通过！
```

## 💡 使用建议

### Git钩子（自动化）
- ✅ **适合场景**: 提交文档时自动质量检查
- ✅ **优点**: 无需手动操作，强制质量标准
- ✅ **建议**: 保持开启，确保文档质量

### Docs-Manager Skill（智能助手）
- ✅ **适合场景**: 复杂的文档管理任务
- ✅ **优点**: 自然语言交互，智能分析
- ✅ **建议**: 用于定期维护、归档、报告生成

### 手动工具（精确控制）
- ✅ **适合场景**: 需要精确控制参数
- ✅ **优点**: 完全可控，灵活配置
- ✅ **建议**: 特殊需求时使用

## 🔧 配置建议

### 推荐配置（团队协作）

```yaml
# .claude/settings.json
{
  "hooks": {
    "pre-commit": true,  # 启用Git钩子
    "auto-validate": true  # 自动校验
  },
  "skills": {
    "docs-manager": {
      "enabled": true,
      "auto-index": "weekly",  # 每周自动生成索引
      "quality-threshold": 80  # 质量阈值
    }
  }
}
```

## ❓ 常见问题

### Q1: Git钩子太严格，如何临时跳过？
**A**: 使用 `git commit --no-verify`（不推荐，仅在紧急情况使用）

### Q2: Skill识别不准确怎么办？
**A**: 使用更明确的指令，如 "运行validate-docs.js校验docs目录"

### Q3: 如何查看Git钩子的输出？
**A**: 钩子会直接显示在终端，错误会阻止提交并显示详细信息

### Q4: Skill能处理其他项目的文档吗？
**A**: 当前Skill专门为AITY VIP项目配置，可以修改skill.md适配其他项目
