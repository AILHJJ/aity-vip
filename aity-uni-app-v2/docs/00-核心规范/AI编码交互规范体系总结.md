### 规范1: 提交即编译
**规则**: 每次Git提交后必须编译生产版本

**原因**:
- ✅ 确保代码可正常编译
- ✅ 及时发现编译问题
- ✅ 保证编译产物随时可部署
- ✅ 避免问题累积

**执行**:
```bash
git add . && git commit -m "xxx" && git push && npm run build:h5 && npm run build:mp-weixin
```

---

### 规范2: 概念清晰明确
**最重要**: 消息标签 vs 消息类型

| 维度 | 消息标签 | 消息类型 |
|------|---------|---------|
| 含义 | 推送给谁 | 什么内容 |
| 可见性 | 仅管理员 | 所有用户 |
| 示例 | 短线VIP | 盘前点评 |
| 代码 | MESSAGE_TAGS | MESSAGE_TYPES |

**记忆口诀**: **"消息标签表示推送给谁，消息类型表示什么内容"**
