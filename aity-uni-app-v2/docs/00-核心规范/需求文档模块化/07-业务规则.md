## 7.1 消息可见性规则

### 7.1.1 规则定义

```
规则名称: 消息标签可见性控制
目的: 根据用户角色和消息标签,控制消息的可见范围
```

### 7.1.2 规则逻辑

#### VIP中线用户

**可见条件**:
```javascript
IF (user.role === 'vip_mid' OR user.role === 'admin' OR user.role === 'super_admin')
   AND (message.tags包含'mid_term' OR message.tags包含'all_users')
THEN 显示该消息
```

**不可见条件**:
```javascript
IF message.tags仅包含'short_term' (不包含'all_users')
THEN 不显示该消息
```

#### VIP短线用户

**可见条件**:
```javascript
IF (user.role === 'vip_short' OR user.role === 'admin' OR user.role === 'super_admin')
   AND (message.tags包含'short_term' OR message.tags包含'all_users')
THEN 显示该消息
```

**不可见条件**:
```javascript
IF message.tags仅包含'mid_term' (不包含'all_users')
THEN 不显示该消息
```

#### 体验用户

**可见条件**:
```javascript
IF user.role === 'trial' OR user.role === 'admin' OR user.role === 'super_admin'
THEN 显示所有消息
```

**说明**: 体验用户可以查看所有类型的消息,但有时间限制(7天)

### 7.1.3 标签组合规则

| 标签组合 | VIP中线 | VIP短线 | 体验用户 | 管理员 |
|---------|---------|---------|---------|--------|
| [mid_term] | ✅ | ❌ | ✅ | ✅ |
| [short_term] | ❌ | ✅ | ✅ | ✅ |
| [all_users] | ✅ | ✅ | ✅ | ✅ |
| [mid_term, all_users] | ✅ | ✅ | ✅ | ✅ |
| [short_term, all_users] | ✅ | ✅ | ✅ | ✅ |

### 7.1.4 实现示例

```javascript
// 后端过滤逻辑 (API)
function canViewMessage(user, message) {
  // 管理员和体验用户可查看所有消息
  if (['admin', 'super_admin', 'trial'].includes(user.role)) {
    return true;
  }

  const tags = message.tags || [];

  // VIP中线用户
  if (user.role === 'vip_mid') {
    return tags.includes('mid_term') || tags.includes('all_users');
  }

  // VIP短线用户
  if (user.role === 'vip_short') {
    return tags.includes('short_term') || tags.includes('all_users');
  }

  return false;
}

// 前端筛选逻辑
function filterMessagesByTag(messages, userRole) {
  return messages.filter(msg => {
    const tags = msg.tags || [];

    switch (userRole) {
      case 'vip_mid':
        return tags.includes('mid_term') || tags.includes('all_users');
      case 'vip_short':
        return tags.includes('short_term') || tags.includes('all_users');
      case 'trial':
      case 'admin':
      case 'super_admin':
        return true;
      default:
        return false;
    }
  });
}
```

## 7.2 讨论可见性规则 (v1.6.0更新)

### 7.2.1 规则定义

```
规则名称: 讨论私密性控制
目的: 根据讨论的可见性设置,控制讨论的可见范围
版本: v1.6.0新增
```

### 7.2.2 规则逻辑

#### 公开讨论

**可见范围**: 所有用户

```javascript
IF discussion.visibility === 'public'
THEN 所有用户可见
```

#### 私密讨论

**可见范围**: 仅管理员和讨论发起者

```javascript
IF discussion.visibility === 'private'
   AND (user.role === 'admin' OR user.role === 'super_admin' OR user.id === discussion.userId)
THEN 可见

IF discussion.visibility === 'private'
   AND (user.role !== 'admin' AND user.role !== 'super_admin' AND user.id !== discussion.userId)
THEN 不可见
```

### 7.2.3 私密讨论标识

**列表显示**:
- 图标: 🔒
- 位置: 讨论标题后面
- 可见: 仅管理员和发起者

**详情页显示**:
- 标识: "私密讨论"文字
- 位置: 页面顶部
- 样式: 红色背景,白色文字

### 7.2.4 实现示例

```javascript
// 后端过滤逻辑
function canViewDiscussion(user, discussion) {
  // 公开讨论,所有人可见
  if (discussion.visibility === 'public') {
    return true;
  }

  // 私密讨论,仅管理员和发起者可见
  if (discussion.visibility === 'private') {
    const isAdmin = ['admin', 'super_admin'].includes(user.role);
    const isCreator = user.id === discussion.userId;
    return isAdmin || isCreator;
  }

  return false;
}

// 前端显示判断
function shouldShowDiscussion(user, discussion) {
  // 公开讨论
  if (discussion.visibility === 'public') {
    return true;
  }

  // 私密讨论
  if (discussion.visibility === 'private') {
    return user.isAdmin || user.id === discussion.userId;
  }

  return false;
}
```

### 7.2.5 可见性对比

| 讨论类型 | 列表显示 | 详情访问 | 回复权限 | 删除权限 |
|---------|---------|---------|---------|---------|
| **公开讨论** | 所有用户 | 所有用户 | 仅管理员 | 仅管理员+发起者 |
| **私密讨论** | 仅管理员+发起者 | 仅管理员+发起者 | 仅管理员 | 仅管理员+发起者 |

## 7.3 VIP到期规则

### 7.3.1 规则定义

```
规则名称: 体验用户到期自动禁用
目的: 控制体验用户的使用期限,促进转化
```

### 7.3.2 规则逻辑

#### 创建体验用户

```javascript
// 创建时自动设置到期时间
function createTrialUser() {
  const now = new Date();
  const expireDate = new Date(now.getTime() + 7 * 24 * 60 * 60 * 1000); // 7天后

  return {
    role: 'trial',
    status: 'active',
    expireDate: expireDate.toISOString().split('T')[0] // YYYY-MM-DD
  };
}
```

#### 检查到期状态

```javascript
// 每次登录时检查
function checkUserExpireStatus(user) {
  if (user.role !== 'trial') {
    return { active: true };
  }

  const now = new Date();
  const expireDate = new Date(user.expireDate);

  if (now > expireDate) {
    // 已到期,禁用账号
    return {
      active: false,
      reason: 'VIP已到期',
      action: 'contact_admin'
    };
  }

  // 计算剩余天数
  const daysLeft = Math.ceil((expireDate - now) / (24 * 60 * 60 * 1000));

  return {
    active: true,
    daysLeft: daysLeft,
    message: `试用期剩余 ${daysLeft} 天`
  };
}
```

#### 定时任务检查

```javascript
// 每天凌晨执行,禁用到期用户
async function disableExpiredTrialUsers() {
  const now = new Date();
  const expiredUsers = await User.findAll({
    where: {
      role: 'trial',
      status: 'active',
      expireDate: {
        [lt]: now.toISOString().split('T')[0]
      }
    }
  });

  for (const user of expiredUsers) {
    await user.update({ status: 'disabled' });
  }

  console.log(`已禁用 ${expiredUsers.length} 个到期体验用户`);
}
```

### 7.3.3 到期处理流程

```
用户登录
├── 检查role === 'trial'
├── 检查expireDate < today
│   ├── 是: 禁用账号
│   │   ├── status: 'disabled'
│   │   └── 提示: "VIP已到期,请联系管理员"
│   └── 否: 正常登录
│       └── 显示剩余天数
```

### 7.3.4 续费规则

**管理员操作**:
- 修改用户角色: trial → vip_mid / vip_short
- 延长到期时间: 更新expireDate字段
- 重新激活: status: disabled → active

**自动转换**:
- 不支持自动转换
- 需要管理员手动处理

## 7.4 消息发布规则

### 7.4.1 发布权限

```javascript
IF user.role === 'admin' OR user.role === 'super_admin'
THEN 允许发布消息
ELSE 不允许发布消息
```

### 7.4.2 消息状态

**草稿** (draft):
- 保存到本地localStorage
- 不发送到服务器
- 可继续编辑

**已发布** (published):
- 保存到服务器
- 推送到用户列表
- 不可编辑 (仅可删除)

### 7.4.3 消息限制

| 限制项 | 限制值 | 说明 |
|-------|--------|------|
| 标题长度 | 1-200字符 | 前端验证 |
| 内容长度 | 1-10000字符 | 前端验证 |
| 每日发布数 | 无限制 | - |
| 图片数量 | 最多9张 | 前端限制 |

## 7.5 讨论回复规则

### 7.5.1 回复权限

```javascript
IF user.role === 'admin' OR user.role === 'super_admin'
THEN 允许回复讨论
ELSE 不允许回复讨论
```

### 7.5.2 回复状态

**待回复** (pending):
- 用户发起讨论后的初始状态
- 管理员未回复

**已回复** (replied):
- 管理员已回复
- 用户可查看回复内容

### 7.5.3 回复通知

**通知触发**:
- 管理员回复讨论后
- 系统自动发送通知给用户

**通知方式**:
- 当前: 仅在讨论列表中显示状态
- 规划中: 推送通知、邮件通知
