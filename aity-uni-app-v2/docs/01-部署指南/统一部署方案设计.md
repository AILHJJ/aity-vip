# 统一部署方案设计

**日期**: 2026-02-06
**目标**: 降低部署难度，自动化前后端更新流程

---

## 📊 当前部署流程分析

### 后端部署（服务器端）
```bash
cd /tmp/AITY/backend && git reset --hard && git pull && pm2 restart aity-backend -f
```

**步骤**:
1. 进入后端目录
2. 硬重置本地修改
3. 拉取最新代码
4. 重启PM2服务

**优点**: 简单快速，无需编译
**缺点**: 只更新后端，不包含前端

---

### 前端部署（当前方案）

#### 方案A: 本地编译 + 上传
```powershell
# 本地Windows
npm run build:h5
# 压缩
# 上传到服务器
# 服务器解压部署
```

**问题**:
- 需要在本地编译
- 手动上传文件
- 流程复杂，容易出错

#### 方案B: 服务器上编译（需要环境）
```bash
cd /tmp/AITY/aity-uni-app-v2
npm run build:h5
cp -r dist/build/h5/* /var/www/html/h5/
```

**问题**:
- 服务器需要安装Node.js和npm依赖
- 编译时间长
- 占用服务器资源

---

## 🎯 统一部署方案

### 方案1: Git同步 + 本地编译（推荐）

#### 核心思路
- 后端：直接在服务器上git pull（无需编译）
- 前端：本地编译，自动上传到服务器

#### 脚本设计

**服务器端统一更新脚本** (`/tmp/AITY/deploy.sh`):
```bash
#!/bin/bash
set -e

echo "========================================="
echo "AITY 统一部署脚本"
echo "========================================="
echo ""

# 1. 更新后端
echo "步骤1: 更新后端..."
cd /tmp/AITY/backend
git reset --hard
git pull origin feature/iteration-1
echo "✅ 后端更新完成"
echo ""

# 2. 重启后端服务
echo "步骤2: 重启后端服务..."
pm2 restart aity-backend -f
echo "✅ 后端服务已重启"
echo ""

# 3. 检查前端编译产物
echo "步骤3: 检查前端编译产物..."
if [ -f /tmp/h5-upload.zip ]; then
    echo "发现前端编译产物，开始部署..."

    # 备份旧版本
    if [ -d /var/www/html/h5 ]; then
        cp -r /var/www/html/h5 /var/www/html/h5-backup-$(date +%Y%m%d-%H%M%S)
    fi

    # 部署新版本
    mkdir -p /var/www/html/h5
    unzip -o /tmp/h5-upload.zip -d /var/www/html/h5/
    chown -R www-data:www-data /var/www/html/h5
    chmod -R 755 /var/www/html/h5

    # 清理临时文件
    rm -f /tmp/h5-upload.zip

    echo "✅ 前端部署完成"
else
    echo "⚠️  未发现前端编译产物，跳过前端部署"
fi

echo ""
echo "========================================="
echo "部署完成！"
echo "后端: 已更新并重启"
echo "前端: " [ -f /var/www/html/h5/index.html ] && echo "已部署" || echo "未更新"
echo "========================================="
```

**Windows本地自动化脚本** (`scripts\full-deploy.bat`):
```batch
@echo off
echo ========================================
echo AITY 完整部署流程
echo ========================================
echo.

REM 1. 本地编译H5
echo 步骤1: 编译H5前端...
cd /d D:\your-mcp-proxy\AITY_VIP\aity-uni-app-v2
call npm run build:h5
if errorlevel 1 (
    echo [错误] H5编译失败
    pause
    exit /b 1
)
echo ✅ H5编译成功
echo.

REM 2. 压缩H5文件
echo 步骤2: 压缩H5文件...
cd dist\build
if exist h5-upload.zip del h5-upload.zip
powershell -Command "Compress-Archive -Path h5\* -DestinationPath h5-upload.zip -Force"
echo ✅ 压缩完成
echo.

REM 3. 上传到服务器
echo 步骤3: 上传H5到服务器...
scp h5-upload.zip root@111.48.74.245:/tmp/
if errorlevel 1 (
    echo [错误] 上传失败
    pause
    exit /b 1
)
echo ✅ 上传成功
echo.

REM 4. 在服务器上执行统一部署脚本
echo 步骤4: 在服务器上执行部署...
echo （这将自动更新后端并部署前端）
ssh root@111.48.74.245 "bash /tmp/AITY/deploy.sh"
if errorlevel 1 (
    echo [错误] 服务器部署失败
    pause
    exit /b 1
)
echo.

echo ========================================
echo 部署成功完成！
echo 后端: 已更新
echo 前端: 已部署
echo 访问: http://111.48.74.245/h5/
echo ========================================
pause
```

### 方案2: 服务器统一部署（需要编译环境）

#### 前提条件
服务器已安装Node.js环境和npm依赖

#### 统一脚本 (`/tmp/AITY/deploy-all.sh`):
```bash
#!/bin/bash
set -e

echo "========================================="
echo "AITY 完整部署脚本（服务器端编译）"
echo "========================================="
echo ""

# 1. 更新后端
echo "步骤1: 更新后端..."
cd /tmp/AITY/backend
git reset --hard
git pull origin feature/iteration-1
echo "✅ 后端更新完成"
echo ""

# 2. 重启后端服务
echo "步骤2: 重启后端服务..."
pm2 restart aity-backend -f
echo "✅ 后端服务已重启"
echo ""

# 3. 编译前端
echo "步骤3: 编译H5前端..."
cd /tmp/AITY/aity-uni-app-v2
npm run build:h5
echo "✅ H5编译完成"
echo ""

# 4. 部署前端
echo "步骤4: 部署H5前端..."
# 备份
if [ -d /var/www/html/h5 ]; then
    cp -r /var/www/html/h5 /var/www/html/h5-backup-$(date +%Y%m%d-%H%M%S)
fi

# 部署
mkdir -p /var/www/html/h5
cp -r dist/build/h5/* /var/www/html/h5/
chown -R www-data:www-data /var/www/html/h5
chmod -R 755 /var/www/html/h5
echo "✅ H5部署完成"
echo ""

echo "========================================="
echo "部署完成！"
echo "后端: 已更新并重启"
echo "前端: 已编译并部署"
echo "访问: http://111.48.74.245/h5/"
echo "========================================="
```

## ✅ 优势分析

### 统一方案的优势

1. **降低部署难度**
   - 一键部署，无需手动操作多个步骤
   - 自动化处理，减少人为错误

2. **提高效率**
   - 前后端同步更新
   - 无需手动SSH到服务器

3. **版本一致**
   - 确保前后端使用同一分支代码
   - 避免版本不匹配问题

4. **灵活选择**
   - 可选择完整部署或仅更新后端/前端
   - 适应不同场景需求

## 🔧 实施步骤

### 第一步：准备服务器端脚本

在服务器上创建统一部署脚本：

```bash
# SSH登录服务器
ssh root@111.48.74.245

# 创建脚本
cat > /tmp/AITY/deploy.sh << 'EOF'
#!/bin/bash
set -e
echo "========================================="
echo "AITY 统一部署脚本"
echo "========================================="
echo ""

# 更新后端
echo "步骤1: 更新后端..."
cd /tmp/AITY/backend
git reset --hard
git pull origin feature/iteration-1
echo "✅ 后端更新完成"

# 重启后端
echo "步骤2: 重启后端服务..."
pm2 restart aity-backend -f
echo "✅ 后端服务已重启"

# 部署前端（如果有编译产物）
echo "步骤3: 部署前端..."
if [ -f /tmp/h5-upload.zip ]; then
    [ -d /var/www/html/h5 ] && cp -r /var/www/html/h5 /var/www/html/h5-backup-$(date +%Y%m%d-%H%M%S)
    mkdir -p /var/www/html/h5
    unzip -o /tmp/h5-upload.zip -d /var/www/html/h5/
    chown -R www-data:www-data /var/www/html/h5
    chmod -R 755 /var/www/html/h5
    rm -f /tmp/h5-upload.zip
    echo "✅ 前端部署完成"
else
    echo "⚠️  未发现前端编译产物"
fi

echo ""
echo "========================================="
echo "部署完成！"
echo "========================================="
EOF

# 添加执行权限
chmod +x /tmp/AITY/deploy.sh
```
