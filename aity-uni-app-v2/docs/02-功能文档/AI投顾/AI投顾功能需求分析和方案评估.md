## 二、技术可行性评估

### 2.1 API分析

#### API端点
```
生产环境: https://www.tdx.com.cn/wenda/api/agent/stream/chat
开发环境: http://192.168.4.225:32222/smart-tdx-wenda/api/agent/stream/chat
```

#### 请求方式
```javascript
POST /api/agent/stream/chat
Headers:
  Accept: text/event-stream
  Content-Type: application/json
  tdx-auth: <token>

Body:
{
  "content": "用户问题",
  "agent": "wenda",
  "threadId": "会话ID（可选）",
  "think": false
}
```

#### 响应格式
- **类型**: Server-Sent Events (SSE)
- **特点**: 流式返回，实时展示AI回答

### 2.2 关键技术点

#### ✅ 优势
1. **API可用**: 公网可访问，测试返回401（需要认证）
2. **技术成熟**: 基于SSE的标准流式接口
3. **代码参考**: 有完整的Vue 2实现可参考
4. **uni-app支持**: 完全支持fetch和SSE

#### ⚠️ 挑战
1. **认证机制**: 需要tdx-auth token（可能需要登录对接）
2. **跨域问题**: 小程序中需要配置合法域名
3. **流式处理**: 需要正确处理SSE数据流
4. **会话管理**: threadId的存储和管理

### 2.3 uni-app兼容性

| 平台 | fetch支持 | SSE支持 | 状态 |
|------|----------|---------|------|
| H5 | ✅ | ✅ | 完全支持 |
| 微信小程序 | ✅ | ⚠️ | 需要配置request合法域名 |
| APP | ✅ | ✅ | 完全支持 |

## 三、认证方案设计

### 3.1 方案A: 使用现有token（推荐）

**前提**: 通达信提供统一的SSO登录

**流程**:
1. 用户在AITY VIP登录
2. 后端调用通达信SSO获取tdx-auth
3. 返回给前端并存储
4. 调用AI接口时携带tdx-auth

**优点**:
- ✅ 统一认证体验
- ✅ 安全性高
- ✅ 用户无感知

**缺点**:
- ⚠️ 需要通达信提供SSO接口
- ⚠️ 需要后端配合

### 3.2 方案B: 使用固定token（临时方案）

**前提**: 通达信提供测试token或无认证token

**流程**:
1. 硬编码tdx-auth在配置文件中
2. 所有用户共享一个token
3. 调用AI接口时使用

**优点**:
- ✅ 实现简单
- ✅ 快速上线

**缺点**:
- ⚠️ 安全性低
- ⚠️ 无法追踪用户行为
- ⚠️ 可能违反通达信使用政策

### 3.3 方案C: 用户注册获取token（完整方案）

**前提**: 用户需要在通达信注册

**流程**:
1. 新用户首次使用AI投顾
2. 跳转通达信登录/注册
3. 获取tdx-auth并存储
4. 后续直接使用

**优点**:
- ✅ 用户独立token
- ✅ 符合通达信要求

**缺点**:
- ⚠️ 用户体验稍差（需要二次登录）
- ⚠️ 开发成本较高

### 3.4 推荐方案

**阶段性实施**:
1. **Phase 1 (MVP)**: 方案B - 使用固定token快速验证
2. **Phase 2 (正式)**: 方案A - 对接SSO统一认证
3. **Phase 3 (完整)**: 方案C - 支持独立注册

## 五、实现方案对比

### 5.1 方案1: 直接调用（简单）

**实现**:
```javascript
// 前端直接调用通达信API
fetch('https://www.tdx.com.cn/wenda/api/agent/stream/chat', {
  headers: { 'tdx-auth': token }
})
```

**优点**:
- ✅ 实现简单
- ✅ 快速上线

**缺点**:
- ❌ token暴露在前端
- ❌ 跨域问题
- ❌ 无法监控和统计

**适用场景**: 快速验证功能

### 5.2 方案2: 后端代理（推荐）

**实现**:
```javascript
// 前端调用后端
fetch('/api/ai/chat', { ... })

// 后端转发到通达信
fetch('https://www.tdx.com.cn/wenda/api/agent/stream/chat', {
  headers: { 'tdx-auth': backendToken }
})
```

**优点**:
- ✅ token不暴露
- ✅ 无跨域问题
- ✅ 可监控统计
- ✅ 可做缓存和优化

**缺点**:
- ⚠️ 需要后端开发
- ⚠️ 增加一层转发

**适用场景**: 正式生产环境

### 5.3 推荐实施路径

**阶段1: 验证功能**（1-2天）
- 使用方案1直接调用
- 固定token
- 简单对话界面

**阶段2: 生产部署**（3-5天）
- 使用方案2后端代理
- 对接SSO获取token

**阶段3: 优化升级**（持续）

### 9.1 SSE流式处理

```javascript
async function fetchAIResponse(message) {
  const response = await fetch(API_URL, {
    method: 'POST',
    headers: {
      'Accept': 'text/event-stream',
      'Content-Type': 'application/json',
      'tdx-auth': token
    },
    body: JSON.stringify({
      content: message,
      agent: 'wenda',
      threadId: threadId,
      think: false
    })
  })

  const reader = response.body.getReader()
  const decoder = new TextDecoder()

  while (true) {
    const { done, value } = await reader.read()
    if (done) break

    const chunk = decoder.decode(value)
    const lines = chunk.split('\n')

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6))
        // 处理流式数据
        handleMessage(data)
      }
    }
  }
}
```
