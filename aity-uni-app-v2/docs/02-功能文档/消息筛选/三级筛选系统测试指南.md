## 筛选逻辑实现细节

### 数据结构
```javascript
const filters = ref({
  strategy: 'all',      // all | short_term | mid_term
  type: 'all',          // all | pre_market_comment | morning_focus | ...
  timeRange: 'all',     // all | today | 3days | 7days | 30days | custom
  customStartDate: null,
  customEndDate: null
})
```

### 筛选优先级
1. **权限过滤**（最优先）：根据用户角色过滤可见消息
2. **策略筛选**：按消息标签（短线/中线）过滤
3. **类型筛选**：按消息类型过滤
4. **时间筛选**：按创建时间过滤
5. **关键词搜索**（最后）：按标题和内容关键词搜索

### 时间筛选逻辑
- **今天**：从今天 00:00:00 开始
- **最近3天**：从3天前 00:00:00 开始
- **最近7天**：从7天前 00:00:00 开始
- **最近30天**：从30天前 00:00:00 开始
- **自定义**：用户选择的开始日期到结束日期

## 功能特性

### 1. 筛选条件持久化
- 使用 localStorage 保存筛选条件
- 页面刷新后自动恢复上次筛选状态
- 存储键名：`message_filters`

### 2. 筛选结果数量显示
- 实时显示筛选后的消息数量
- 格式：`找到 X 条消息`
- 在筛选面板底部显示

### 3. 重置筛选功能
- 一键重置所有筛选条件到初始状态
- 重置按钮仅在存在激活筛选时显示
- 点击后所有筛选条件恢复为 `all`

### 4. 自定义时间选择
- 使用 uni-app 原生 picker 组件
- 支持开始日期和结束日期选择
- 开始日期不能晚于结束日期
- 结束日期不能晚于今天

### 5. 筛选面板交互
- 支持展开/收起筛选面板
- 有激活筛选条件时自动展开
- 筛选条件变化时自动刷新结果

## 已知问题和注意事项

1. **时间筛选依赖 dayjs**
   - 确保 dayjs 已正确安装
   - 时间处理使用 UTC 时间

2. **localStorage 限制**
   - 某些平台可能限制 localStorage 使用
   - 已添加错误处理

3. **筛选性能**
   - 当前使用前端筛选
   - 如果消息量很大（> 1000），考虑后端筛选

4. **类型映射**
   - 某些消息类型可能在后端不存在
   - 前端显示时会使用原始值
