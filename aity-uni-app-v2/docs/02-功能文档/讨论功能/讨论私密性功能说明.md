## 一、功能概述

### 业务背景

为了提供交流互动平台，同时保证合规性以及不影响其他用户的判断，我们引入了讨论的私密性控制机制。

### 核心原则

1. **默认私密**: 用户发起讨论时，默认为私密状态
2. **管理员审核**: 管理员可以查看私密讨论并决定是否公开
3. **权限隔离**: 私密讨论只有发起人和管理员可见
4. **灵活切换**: 管理员可以随时切换讨论的可见性

---

## 二、可见性类型

### 1. 私密讨论 (private)

**默认状态**

**可见范围**:
- ✅ 讨论发起者
- ✅ 管理员（super_admin、admin）
- ❌ 其他普通用户

**使用场景**:
- 用户对管理员发布的内容有疑问
- 需要私密咨询的问题
- 可能包含敏感信息的讨论
- 不确定是否适合公开的内容

**视觉标识**:
- 🔒 锁图标
- 橙色"私密"标签

### 2. 公开讨论 (public)

**需管理员审核后公开**

**可见范围**:
- ✅ 所有用户
- ✅ 访客（如果有访客权限）

**使用场景**:
- 管理员审核通过的优质讨论
- 具有普遍参考价值的问题
- 管理员认为适合公开的内容

**视觉标识**:
- 🌐 地球图标
- 绿色"公开"标签

### 4.2 讨论列表权限过滤

**前端过滤逻辑**:
```javascript
// aity-uni-app-v2/src/pages/discussions/discussions.vue
const filteredDiscussions = computed(() => {
  let filtered = discussions.value

  // 权限过滤：私密讨论只有管理员和发起者可见
  if (!userStore.isAdmin) {
    filtered = filtered.filter(discussion => {
      // 公开讨论所有人可见
      if (discussion.visibility === 'public') {
        return true
      }
      // 私密讨论只有发起者可见
      if (discussion.visibility === 'private') {
        return discussion.creatorId === userStore.userInfo?.id
      }
      return false
    })
  }

  return filtered
})
```

**后端过滤逻辑**:
```javascript
// backend/src/controllers/discussionController.js
async function getDiscussions(req, res) {
  const visibilityCondition = []

  if (currentUserRole === 'super_admin' || currentUserRole === 'admin') {
    // 管理员可以查看所有讨论
  } else {
    // 普通用户只能查看公开讨论或自己发起的讨论
    visibilityCondition.push(
      { visibility: 'public' },
      { userId: currentUserId }
    )
    where[Op.or] = visibilityCondition
  }
}
```

### 4.3 讨论详情权限检查

**后端权限验证**:
```javascript
async function getDiscussionById(req, res) {
  let hasPermission = false

  if (currentUserRole === 'super_admin' || currentUserRole === 'admin') {
    // 管理员可以查看所有讨论
    hasPermission = true
  } else if (discussion.visibility === 'public') {
    // 公开讨论所有人可见
    hasPermission = true
  } else if (discussion.userId === currentUserId) {
    // 私密讨论只有发起者和管理员可见
    hasPermission = true
  }

  if (!hasPermission) {
    return res.status(403).json(forbidden('No permission'))
  }
}
```

### 4.5 回复权限控制

**后端权限检查**:
```javascript
async function addDiscussionReply(req, res) {
  let canReply = false

  if (senderRole === 'super_admin' || senderRole === 'admin') {
    // 管理员可以回复所有讨论
    canReply = true
  } else if (discussion.visibility === 'public') {
    // 公开讨论所有人可以回复
    canReply = true
  } else if (discussion.userId === senderId) {
    // 发起者可以回复自己的讨论
    canReply = true
  }

  if (!canReply) {
    return res.status(403).json(forbidden('No permission to reply'))
  }
}
```

**管理员回复时可修改可见性**:
```javascript
// 更新讨论状态和可见性
const updateData = { status: 'replied' }

if ((senderRole === 'super_admin' || senderRole === 'admin') && visibility) {
  // 只有管理员可以修改可见性
  updateData.visibility = visibility
}

await discussion.update(updateData)
```

## 六、典型使用场景

### 场景1：用户咨询问题

**流程**:
1. 用户在消息详情页点击"发起讨论"
2. 默认选择"私密"可见性
3. 填写问题内容并提交
4. 讨论创建为私密状态
5. 只有用户本人和管理员可以看到
6. 管理员回复后，用户收到通知
7. 管理员可以选择是否将讨论公开

### 场景2：管理员审核并公开

**流程**:
1. 管理员查看讨论列表，看到私密讨论
2. 点击进入讨论详情
3. 查看讨论内容和已有的回复
4. 判断该讨论具有普遍参考价值
5. 点击"修改可见性"，选择"公开"
6. 系统更新讨论状态为公开
7. 所有用户现在可以看到这个讨论

### 场景3：公开讨论的互动

**流程**:
1. 管理员将讨论改为公开
2. 所有用户在讨论列表中可以看到
3. 普通用户可以查看和回复
4. 讨论形成群体互动
5. 积累更多有价值的回复

### 场景4：私密讨论的后续处理

**流程**:
1. 管理员查看私密讨论
2. 判断内容不适合公开（如包含敏感信息）
3. 保持私密状态
4. 仅在私密范围内继续交流
5. 必要时建议用户重新发起公开讨论

## 七、安全和合规性

### 7.1 数据安全

**权限隔离**:
- ✅ 前端过滤：用户界面不显示无权限的讨论
- ✅ 后端验证：API层严格检查用户权限
- ✅ 数据库隔离：SQL查询包含权限条件

**防止信息泄露**:
- 用户无法通过API访问私密讨论
- 用户无法猜测讨论ID来访问
- 列表API只返回有权限的数据

### 7.2 合规性保障

**内容审核机制**:
- 默认私密避免不当内容扩散
- 管理员审核后再公开
- 可追溯的审核记录

**用户隐私保护**:
- 私密讨论保护用户隐私
- 用户可以选择公开或保密
- 敏感信息不会意外泄露

### 7.3 审计和追溯

**操作记录**（建议未来实现）:
- 记录谁创建了讨论
- 记录谁修改了可见性

## 九、常见问题解答

### Q1: 为什么默认是私密讨论？

**A**: 为了保证合规性和用户隐私：
- 避免不当内容公开扩散
- 给用户思考的时间
- 管理员可以先审核再决定是否公开
- 保护用户可能包含的敏感信息

### Q2: 私密讨论会被永久保密吗？

**A**: 不一定。管理员可以根据情况：
- 保持私密：如果内容不适合公开
- 改为公开：如果具有普遍参考价值
- 删除讨论：如果违反规定

### Q3: 如何让我的讨论公开？

**A**: 两种方式：
1. 创建时直接选择"公开"
2. 创建私密后，请求管理员改为公开

### Q4: 其他用户能看到我的私密讨论吗？

**A**: 不能。私密讨论的可见范围：
- ✅ 你自己（发起者）
- ✅ 管理员
- ❌ 其他所有用户

### Q5: 管理员回复时会自动公开讨论吗？

**A**: 不会自动公开。但管理员在回复时可以选择是否修改可见性。

### Q6: 公开讨论可以改回私密吗？

**A**: 可以。管理员随时可以修改讨论的可见性。
