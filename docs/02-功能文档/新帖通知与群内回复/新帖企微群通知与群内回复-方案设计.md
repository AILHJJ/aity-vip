# 新帖企微群通知与群内回复 — 方案设计

> 版本：v1.1（2026-09-13，4 项待确认项已定稿）
> 状态：已确认，待实施
> 关联：《SSL证书与自动续期说明.md》（告警渠道共用本方案的群机器人）
>
> **已确认决策**：① 用户回帖也通知；② 通知群仅管理员可见，私密帖内容可直接全推；③ 二期群内回复支持公开/私密可选；④ 机器人命名：一期`AITY通知助手`、二期`AITY回帖助手`

## 一、背景与目标

**痛点**：用户在 AITY 产品内发新帖（讨论/提问），管理员无法第一时间感知，处理不及时。

**目标**：
1. 一期（优先）：用户发新帖 → 企业微信群**秒级通知**管理员，点链接直达帖子处理
2. 二期（增强）：管理员在群里 @机器人 直接回复帖子，无需打开产品

**同群复用**：SSL 证书续期失败告警也推送到同一个群机器人，一个群管所有运维+业务通知。

## 二、总体架构

```
┌─────────────────────────────────────────────────────┐
│  企业微信群「AITY运维与客服」                          │
│  └─ 群机器人（webhook，单向推送 ← 一期用这个）           │
│  └─ 智能机器人（API模式，双向对话 ← 二期用这个）         │
└─────────────────────────────────────────────────────┘
        ↑ 一期推送                    ↓ 二期接收(@机器人)
┌──────────────────────┐      ┌──────────────────────┐
│ AITY 后端 (3001)      │      │ AITY 后端新增机器人    │
│ · createDiscussion    │      │ 消息接收与身份校验      │
│   成功后推送通知        │      │ → addDiscussionReply │
│ · 服务器SSL告警脚本    │      └──────────────────────┘
└──────────────────────┘
```

## 三、一期：新帖单向通知（工作量约 0.5~1 天）

### 3.1 前置：创建群机器人（人工，1 分钟）

群里添加"群机器人"（**普通模式 webhook，不是智能机器人**），拿到 webhook URL，配置到后端 env。

### 3.2 后端改造

**新增 `services/wecomNotifyService.js`**（唯一新增文件，其余为小改）：

```js
// 职责：组装 markdown 消息 → POST webhook → 失败落库重试
async function notifyNewDiscussion(discussion) { ... }
async function notifyNewReply(discussion, reply) { ... }  // 可选开关
async function sendWecomMarkdown(content) { ... }          // 底层发送
```

**挂钩点**（`discussionController.js`）：
- `createDiscussion`（:267）成功后调用 `notifyNewDiscussion` —— **fire-and-forget**，用 `.catch()` 吞错，绝不影响发帖主流程
- `addDiscussionReply`（:371）成功后调用 `notifyNewReply` —— 默认关闭，env 开关控制

**可靠性设计（复用已有 outbox 思路）**：
- 发送成功：不落库，零开销
- 发送失败：写入已有 `NotificationOutbox` 表（新增 `channel='wecom_webhook'`），由现有定时扫描机制重试（需确认扫描器支持多 channel，不支持则加一个 5 分钟间隔的重试 job）

**消息卡片（markdown）**：

```
📢 新帖子提醒
标题：{title}
分类：{category} ｜ 可见性：{公开/私密}
作者：{userName}
摘要：{content前80字}…
时间：{yyyy-MM-dd HH:mm}
👉 处理：https://aity88.online/#/pages/discussion-detail/discussion-detail?id={id}
```

**隐私说明（已确认）**：通知群仅管理员可见，私密帖同样推送完整摘要，不做脱敏。

### 3.3 配置项（backend.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WECOM_WEBHOOK_URL` | 空=禁用 | 群机器人 webhook |
| `WECOM_NOTIFY_ON_CREATE` | `true` | 新帖通知 |
| `WECOM_NOTIFY_ON_REPLY` | `true` | 用户回帖通知（**管理员自己的回复不推**，避免噪音） |
| `WECOM_NOTIFY_DRY_RUN` | `false` | 调试用，只打日志不发送 |

### 3.4 SSL 告警同渠道（服务器侧，与后端无关）

- acme.sh 续期失败 → curl 同一 webhook 推告警
- 服务器每周兜底巡检 cron，证书 <15 天推告警
- 已在《SSL证书与自动续期说明.md》中规划，待 URL 到位即配置

## 四、二期：群内直接回复（工作量约 2~3 天）

### 4.1 技术选型

群机器人 webhook **只能发不能收**。接收群内 @消息 需要二选一：

| 方案 | 说明 | 结论 |
|---|---|---|
| 企业微信自建应用消息回调 | 需在管理后台建应用+配回调 URL+加解密 | 需暴露公网回调，配置繁琐 |
| **智能机器人 API 模式（推荐）** | 就是之前截图里那种（Bot ID + Secret），官方 Node SDK 长连接收消息，**无需公网回调** | ✅ 复用截图入口，接入门槛低 |

### 4.2 交互设计

```
（一期通知消息里带帖子编号）
管理员在群里发：@AITY助手 回复 1024 感谢反馈，已处理，请查看最新版本

机器人流程：
  1. 解析指令：帖子ID=1024，内容=感谢反馈…
  2. 校验发送者是否已绑定管理员身份
  3. 调用 addDiscussionReply（复用后端现有逻辑，isPrivate=false 公开回复）
  4. 群里回执：✅ 已回复帖子《xxx》：https://aity88.online/#/pages/...
```

**身份绑定（关键安全设计）**：
- 首次使用：管理员在群里 @机器人 `绑定 <产品后台生成的绑定码>`
- 后端维护映射表（企微 userid ↔ AITY admin 账号），未绑定者指令一律拒绝并提示

**回复可见性选择（已确认不限定）**：

```
@AITY助手 回复 1024 感谢反馈…            → 默认公开回复
@AITY助手 回复 1024 公开 感谢反馈…        → 公开回复
@AITY助手 回复 1024 私密 这是私密内容…     → 私密回复（仅帖主与管理员可见）
```

解析规则：`回复 <帖子ID> [公开|私密] <内容>`，可见性关键字可选，缺省=公开。私密回复在群里回执时**不回显内容**，仅提示"已私密回复帖子《xxx》"。

### 4.3 难点与对策

| 难点 | 对策 |
|---|---|
| 企微消息可能重试推送 | 以 msgid 幂等去重 |
| 指令解析容错 | 严格格式校验，格式不对返回使用帮助 |
| 私密帖群内回复泄露 | 私密帖内容在群内可见（群仅管理员，已确认）；但群内**私密回复的回执不回显内容**，防截屏转发外泄 |
| 内容长度/注入 | 长度截断 500 字，纯文本入库走现有 reply 校验链 |
| 机器人掉线 | 长连接自动重连 + 心跳日志，掉线超 10 分钟推 webhook 告警（自监控） |
