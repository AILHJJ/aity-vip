# 新帖企微群通知与群内回复 — 方案设计

> 版本：v1.2（2026-09-13，二期方案定稿，含发帖+回帖+图文）
> 状态：二期开发中
> 关联：《SSL证书与自动续期说明.md》（告警渠道共用本方案的群机器人）
>
> **已确认决策**：① 用户回帖也通知；② 通知群仅管理员可见，私密帖内容可直接全推；③ 二期群内回复支持公开/私密可选；④ 机器人命名：一期`AITY通知助手`、二期`AITY回帖助手`
> **二期新增决策**：⑤ 群内发帖可选公开/私密；⑥ 回帖方案甲（引用通知自动识别帖子ID）；⑦ 图文一起做（media_id/aeskey 转存）

## 一、背景与目标

**痛点**：用户在 AITY 产品内发新帖（讨论/提问），管理员无法第一时间感知，处理不及时。

**目标**：
1. 一期（优先）：用户发新帖 → 企业微信群**秒级通知**管理员，点链接直达帖子处理
2. 二期（增强）：管理员在群里 @机器人 直接回复帖子，无需打开产品

**同群复用**：SSL 证书续期失败告警也推送到同一个群机器人，一个群管所有运维+业务通知。

## 二、总体架构

```
┌─────────────────────────────────────────────────────┐
│  企业微信群「AITY运维与客服」                          │
│  └─ 群机器人（webhook，单向推送 ← 一期用这个）           │
│  └─ 智能机器人（API模式，双向对话 ← 二期用这个）         │
└─────────────────────────────────────────────────────┘
        ↑ 一期推送                    ↓ 二期接收(@机器人)
┌──────────────────────┐      ┌──────────────────────┐
│ AITY 后端 (3001)      │      │ AITY 后端新增机器人    │
│ · createDiscussion    │      │ 消息接收与身份校验      │
│   成功后推送通知        │      │ → addDiscussionReply │
│ · 服务器SSL告警脚本    │      └──────────────────────┘
└──────────────────────┘
```

## 三、一期：新帖单向通知（工作量约 0.5~1 天）

### 3.1 前置：创建群机器人（人工，1 分钟）

群里添加"群机器人"（**普通模式 webhook，不是智能机器人**），拿到 webhook URL，配置到后端 env。

### 3.2 后端改造

**新增 `services/wecomNotifyService.js`**（唯一新增文件，其余为小改）：

```js
// 职责：组装 markdown 消息 → POST webhook → 失败落库重试
async function notifyNewDiscussion(discussion) { ... }
async function notifyNewReply(discussion, reply) { ... }  // 可选开关
async function sendWecomMarkdown(content) { ... }          // 底层发送
```

**挂钩点**（`discussionController.js`）：
- `createDiscussion`（:267）成功后调用 `notifyNewDiscussion` —— **fire-and-forget**，用 `.catch()` 吞错，绝不影响发帖主流程
- `addDiscussionReply`（:371）成功后调用 `notifyNewReply` —— 默认关闭，env 开关控制

**可靠性设计（复用已有 outbox 思路）**：
- 发送成功：不落库，零开销
- 发送失败：写入已有 `NotificationOutbox` 表（新增 `channel='wecom_webhook'`），由现有定时扫描机制重试（需确认扫描器支持多 channel，不支持则加一个 5 分钟间隔的重试 job）

**消息卡片（markdown）**：

```

标题：{title}
```

**隐私说明（已确认）**：通知群仅管理员可见，私密帖同样推送完整摘要，不做脱敏。

### 3.3 配置项（backend.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WECOM_WEBHOOK_URL` | 空=禁用 | 群机器人 webhook |
| `WECOM_NOTIFY_ON_CREATE` | `true` | 新帖通知 |
| `WECOM_NOTIFY_ON_REPLY` | `true` | 用户回帖通知（**管理员自己的回复不推**，避免噪音） |

## 四、二期：群内双向操作（发帖 + 回帖，含图文）（工作量约 3~4 天）

> **核心定位**：管理员在企微群里 @机器人 直接完成"发帖"和"回帖"，结果实时同步到小程序/H5，全程不切端。

### 4.1 技术选型（已确认）

智能机器人 API 模式 + **长连接（WebSocket）**，无需公网回调地址：

| 项 | 值 |
|---|---|
| WebSocket 地址 | `wss://openws.work.weixin.qq.com` |
| 握手命令 | `aibot_subscribe`（含 `bot_id` + `secret`） |
| 收消息命令 | `aibot_msg_callback`（含 msgid/chatid/from.userid/msgtype/text/image） |
| 回消息命令 | `aibot_respond_msg`（支持 text/markdown/image 等） |
| 心跳 | 30 秒 `ping`，断线自动重连 |
| Bot 凭据 | Bot ID `aibKOtaw1V2f7AK5z7-XP1ToLB4dIXE6haM`（已创建加群） |

### 4.2 交互设计（含发帖，本次新增）

**场景 A：群内发帖（管理员主动输出内容）**
```
管理员：@AITY回帖助手 发帖 公开 【今日盘前】今天关注xxx板块…
  → 机器人调后端发帖接口（createDiscussion）
  → 帖子同步到小程序/H5「消息中心」
  → 群内回执：✅ 已发布《标题》 https://aity88.online/#/pages/...
```

**场景 B：群内回帖（响应用户，方案甲——引用识别帖子ID）**
```
用户发帖 → 群收到通知（一期）
管理员「引用」这条新帖通知，再输入：@AITY回帖助手 回复 短期看震荡，关注支撑位…
  → 机器人从被引用的消息里识别帖子 ID（无需手抄）
  → 调后端回帖接口（addDiscussionReply）
  → 回复同步到帖子详情（小程序/H5 用户可见）
  → 群内回执：✅ 已回复《标题》
```

**指令格式**：

```
发帖 [公开|私密] <内容>            → 群内发帖，可见性可选，缺省=私密
回复 <帖子ID> [公开|私密] <内容>    → 回帖，缺省=公开
回复 <内容>（引用了通知）          → 方案甲：从被引用消息自动提取帖子ID
绑定 <绑定码>                     → 身份绑定
帮助                            → 返回使用说明
```

### 4.3 图片转存（本次一起做）

**接收图片（管理员发图给机器人）**：长连接图片消息结构为 `image.url`（5 分钟有效）+ `image.aeskey`（解密密钥）。

```
1. 用 image.url 下载加密图片二进制
2. 用 image.aeskey 做 AES-256-CBC 解密（IV = aeskey 前 16 字节，PKCS#7 填充）
3. 解密得到原始图片 → 上传到后端 /api/upload（复用 express-fileupload）
4. 拿到图片 URL → 传给 createDiscussion / addDiscussionReply 的 images 字段
```

**发送图片（机器人回执带图）**：需先上传临时素材拿 media_id（`aibot_upload_media_init` → `chunk` → `finish`），media_id 3 天有效。**首期回执用文本，不发图**（降低复杂度）。

### 4.4 身份绑定（关键安全设计）

- 首次使用：管理员群里 @机器人 `绑定 <绑定码>`，绑定码在用户管理后台生成
- 后端映射表 `wecom_user_bindings`（企微 userid ↔ AITY admin 账号 id）
- **未绑定者指令一律拒绝**，防止外部人通过群乱发帖

### 4.5 后端改造清单

| 改动 | 文件 | 说明 |
|---|---|---|
| 新增机器人服务 | `services/wecomBotService.js` | WebSocket 长连接 + 消息分发 + 图片解密 |
| 新增绑定模型 | `models/WecomUserBinding.js` | 企微 userid ↔ admin 映射 |
| 发帖支持图片 | `Discussion.js` + `discussionController.js` | 补 `images` 字段 + createDiscussion 接 images |
| 复用回帖 | `discussionController.js` addDiscussionReply | 已支持 images，无需改 |
| 配置项 | `.env` | `WECOM_BOT_ID` / `WECOM_BOT_SECRET` |

### 4.6 难点与对策

| 难点 | 对策 |
|---|---|
| 企微消息重试推送 | 以 msgid 幂等去重（内存 Set + 过期清理） |
| 指令解析容错 | 严格格式校验，格式不对返回使用帮助 |
| 图片 url 5 分钟失效 | 收到消息立即下载解密，不落库延迟处理 |
| 私密回复回执泄密 | 私密回复回执不回显内容，仅提示"已私密回复《xxx》" |
| 内容长度/注入 | 长度截断 500 字，纯文本走现有校验链 |
| 机器人掉线 | WebSocket 自动重连 + 心跳日志，掉线超 10 分钟推 webhook 告警 |
