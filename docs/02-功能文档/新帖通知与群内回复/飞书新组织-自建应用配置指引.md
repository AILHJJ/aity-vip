# 飞书自建应用配置指引（详细版 · 可作为换渠道通用参考）

> 用途：在飞书组织里创建并配置一个**互动机器人**（自建应用），供小程序「群内发帖/回帖」使用
> 生成时间：2026-09-16（v2 详细版）
> 本文同时是**换渠道/新建渠道的通用参考**：任何 IM 渠道（钉钉/QQ 等）接入都遵循
> 「创建应用 → 机器人能力 → 事件订阅 → 权限 → 发布 → 拉群 → 后端注册渠道」这套流程

## 〇、当前飞书机器人架构总览（3 个 bot，各司其职）

| bot | 类型 | 消费端 | 职责 | 是否可共用 |
|---|---|---|---|---|
| AI运维助手 | 自定义机器人（webhook） | aity-vip 后端 | 通知推送（新帖/回帖），只发不收 | 独立 webhook，无冲突 |
| AITY智能助手 | 自建应用（长连接） | aity-vip 后端 | 群内互动：@它 发帖/回帖/绑定/帮助 | **不可**与任何其他消费端共用 |
| AI投研分析师 | 自建应用（长连接） | WorkBuddy | 远程操控/知识库问答 | 独立，与小程序无关 |

> ⚠️ 核心规则：**一个自建应用的事件订阅只能有一个消费端**。两个长连接客户端
> 连同一应用时，事件会随机分发到其中之一，两边都时灵时不灵。新建消费端 = 新建应用。

## 一、创建自建应用

1. 浏览器打开 **https://open.feishu.cn** → 右上角确认组织正确 → 「开发者后台」
2. 「创建企业自建应用」→ 填名称/描述/图标 → 创建
3. 记下「凭证与基础信息」页的 **App ID**（cli_ 开头）和 **App Secret**（后面要填到渠道配置）

## 二、添加机器人能力

左侧「应用能力」→ 找「机器人」卡片 → 「添加」。
没有机器人能力，应用无法被拉进群、无法收发消息。

## 三、事件与回调（最关键，3 个动作）

左侧「**事件与回调**」页面下有 3 个页签：**事件配置 / 回调配置 / 加密策略**（注意区分）。

### 3.1 订阅方式（必须）
- 「事件配置」页签顶部 → 订阅方式选「**使用长连接接收事件**」→ **保存**
- ❌ 不要选「将事件发送至开发者服务器」——那需要公网 URL + 域名校验，
  自有域名主体与飞书企业主体不一致时会被拒（我们在企微上踩过同款坑）
- 此页顶部「连接状态」在**后端未连接时显示失败是正常的**，渠道启用后自动变绿

### 3.2 添加事件（必须）
- 「**事件配置**」页签（不是"回调配置"！）→ 「添加事件」
- 搜索「**接收消息**」→ 勾选 **`im.message.receive_v1`** → 保存
- 添加时弹出的所需权限提示 → 一路「确定/开通」（自动勾选权限）

### 3.3 加密策略（可选但建议）
- 「加密策略」页签 → 生成 **Encrypt Key** 并妥善保存
- 我们的后端目前用不到（长连接模式），但留着便于以后扩展

## 四、权限管理

左侧「权限管理」→ 确认以下权限已开通（3.2 添加事件时通常自动带上，缺哪个搜关键词补）：

| 搜索关键词 | 权限 | 说明 |
|---|---|---|
| 接收 | 接收群聊中 @机器人 消息 | 收群消息的核心权限 |
| 获取与发送 | 获取与发送单聊、群组消息 | 回复消息必需 |
| 资源 | 获取消息中的图片资源 | 图片发帖必需 |

## 五、版本发布（不发布 = 全部配置不生效）

1. 「版本管理与发布」→「创建版本」→ 版本号 1.0.0 + 更新说明 → 提交
2. 需要企业管理员审核：
   - 你自己是管理员 → **https://go.feishu.cn/admin** → 应用审核 → 自己通过
   - 不是管理员 → 联系管理员批准（或让管理员给你加「应用管理员」角色）
3. 应用状态变「**已启用**」才算完成
4. ⚠️ 发布之后**又改了事件/权限**的话，需要**再发一个版本**（1.0.1）才会生效——
   页面顶部黄条「版本发布后，当前修改方可生效」就是提示这个

## 六、拉机器人进群

群设置 → 群机器人 → 添加机器人 → 选你的应用 → 添加。

## 七、后端启用渠道（二选一）

### 方式 A：管理后台页面（推荐）
管理后台 → 渠道配置 → 对应渠道 Tab → 填 App ID / Secret / 绑定码 → 开启 → 保存并生效。
保存即热重载，无需重启。

### 方式 B：后端直连数据库（运维用）
`bot_channel_configs` 表 upsert 一条记录（channel/enabled/config JSON）→ `pm2 restart aity-backend`。
单渠道设计：同一时间只有一条 enabled=true，切换渠道 = 改 enabled。

## 八、验证连接（3 个观察点）

1. 后端日志：`pm2 logs aity-backend` 应出现「[飞书渠道] 长连接已建立」「client ready」
2. 开放平台「事件与回调」页：长连接状态变「**已连接**」（绿点）
3. 群里 `@机器人 帮助` → 应回复使用说明

> ⚠️ 时序注意：先启用渠道、后发消息测试。消息发出时 bot 若未启动，不会有任何回复。

## 九、验收测试清单

```
1. @机器人 帮助                → 回复使用说明
2. @机器人 绑定 <绑定码>       → 回复绑定成功
3. @机器人 发帖 # 标题
   正文                        → 回复发帖链接，消息中心可见
4. @机器人 回复 <帖子ID> 内容  → 回帖成功，讨论详情可见
5. 发一张图 + @机器人 发帖 # 图片测试
   正文                        → 图片随帖（可选）
```

## 十、异常排查速查

| 现象 | 排查顺序 |
|---|---|
| @机器人 无任何回复 | ①应用是否已发布？②事件 im.message.receive_v1 是否订阅？③渠道是否已启用（后端日志有无"长连接已建立"）？④测试时间是否早于渠道启用？ |
| 回复"指令格式不正确" | 连接正常，指令写法问题（发「帮助」看格式） |
| 回复"未绑定管理员身份" | 安全机制，先发「绑定 <绑定码>」 |
| 长连接显示连接失败 | 渠道未启用 / App Secret 错误 / 应用未发布 |
| 收到消息但回复失败 | 检查「获取与发送消息」权限 |
| 图片帖图片缺失 | 检查「获取消息中的图片资源」权限 |

## 十一、换渠道开发参考（钉钉/QQ 等）

后端采用渠道抽象，接入新 IM 只需 4 步（代码侧）：

1. 新建 `src/channels/XxxBotChannel.js` 继承 `BotChannel`（src/channels/BotChannel.js），
   实现 start/stop/reply/sendToGroup/downloadImage 五个方法，
   把渠道消息转成统一 ChannelMessage（msgId/userId/chatId/chatType/content/imageObjs/reqId）
2. `src/services/channelFactory.js` 的 switch 里注册新渠道
3. 渠道配置页已按 Tab 动态预留，加一个 Tab 的表单字段即可
4. 指令解析/发帖/回帖/绑定等业务逻辑在 `src/services/botService.js`，渠道无关，直接复用

运维侧流程与本文第一~九章相同（每个平台都有"创建应用→机器人能力→事件订阅→权限→发布"的对等步骤）。
