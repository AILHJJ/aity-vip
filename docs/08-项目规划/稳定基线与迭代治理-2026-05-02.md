## 4. 分支治理策略

### 推荐长期分支模型

| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 生产稳定分支 | 只接受经过验证的 release/hotfix 合并 |
| `develop` | 集成分支 | 后续日常迭代从这里拉 feature 分支 |
| `feature/<topic>` | 功能开发 | 小步提交, 完成后合入 `develop` |
| `release/<version>` | 发布候选 | 从 `develop` 拉出, 只做修复和发布准备 |
| `hotfix/<topic>` | 线上紧急修复 | 从 `main` 拉出, 修复后同时合回 `main` 和 `develop` |

### 当前过渡策略

由于线上可运行版本大概率接近 `develop`, 但尚未通过 SSH 确认线上 Git SHA, 过渡期建议:

1. 暂定 `develop@3735945` 为候选稳定基线。
2. 登录腾讯云服务器确认:
   ```bash
   cd /root/aity-vip/backend
   git branch --show-current
   git rev-parse --short HEAD
   git status --short
   pm2 status
   ```
3. 如果线上 HEAD 等于或早于 `develop@3735945`, 以 `develop` 建立 `release/2026-05-baseline`。
4. 如果线上 HEAD 含有本地没有的补丁, 先从线上导出补丁或拉取远端补齐, 再建立 release。
5. 验证通过后, 将 `release/2026-05-baseline` 合入 `main`, 让 `main` 重新成为生产稳定分支。

### 分支清理建议

待 `release/2026-05-baseline` 建立并验证后:

1. 远端 `feature/iteration-1`: 标记为已完成, 可以删除或保留只读。
2. 本地 `recover/*`: 导出差异后删除。
3. 本地 `backup/*`: 确认不再需要后删除。
4. 本地 `feature/tencent-cloud-docs-fix`: 删除。
5. 新需求统一从 `develop` 或 `release` 拉分支, 不再从旧 `feature/iteration-1` 继续开发。

## 5. 后续迭代计划

### 迭代 0: 基线稳定化

目标: 让团队有一个干净、可运行、可回滚的版本。

范围:

- 确认腾讯云线上后端 Git SHA。
- 统一生产 API 地址为 `https://aity88.online/api`。
- 修正 README、发布清单、脚本提示中的 `8443` 旧描述。
- 建立 `release/2026-05-baseline`。
- 在 release 分支完成健康检查、登录、消息列表、消息详情、发布消息、讨论、行情中心、AI投顾冒烟测试。
- 将稳定 release 合入 `main`。

验收标准:

- `main` 指向一个可部署版本。
- 线上 API health/version 正常。
- 小程序生产构建使用 `https://aity88.online/api`。
- 发布清单可按步骤执行。

### 迭代 1: 项目目录与文档治理

目标: 降低新成员理解成本, 避免重复文档和临时文件干扰开发。

范围:

- 统一文档入口为 `docs/README.md`。
- 将旧散落文档迁移到 `docs/已归档文档/` 或对应一级分类。
- 清理 `docs` 根目录的大型原型 HTML、截图、临时 diff。
- 明确 `frontend/` 是否废弃; 若废弃, 归档或删除; 若保留, 改名并说明用途。
- 整理 `aity-uni-app-v2/` 根目录测试报告、临时脚本和截图。
- 整理 `backend/` 根目录部署脚本、一次性诊断脚本和数据初始化脚本。

验收标准:

- 根目录只保留核心入口文件。
- 文档能从 `docs/README.md` 一跳到达。
- 临时文件不再进入主开发路径。

### 迭代 2: 现有功能补齐与质量修复

目标: 修复当前使用中最影响稳定性的缺口。

候选任务:

- 消息列表搜索。
- 消息筛选体验收口: 策略、类型、时间、重置、空状态。
- 图片上传超时和大文件体验优化。
- 下拉刷新兼容性复核。
- 日期选择器 H5/小程序样式一致性。
- 长按消息卡片快捷操作。
- 统一错误处理和 toast 文案。

验收标准:

- 核心用户路径无阻塞 bug。
- H5 和微信小程序关键页面表现一致。
- 自动化或手工测试清单覆盖核心路径。

### 迭代 3: 行情中心增强

目标: 补齐路线图中未完成的高优先级行情能力。

候选任务:

- 自选股功能前端集成。
- 股票搜索功能。
- 分时图/K线图。
- 自动刷新机制。
- 市场异动监控。

验收标准:

- 用户能搜索股票并加入/移除自选。
- 行情页面能稳定展示关键图表。
- 异常时有降级和错误提示。

### 迭代 4: 推送、导出与离线能力

目标: 补齐需求文档中明确列为规划中的能力。

候选任务:

- 微信小程序订阅消息。
- 浏览器通知或 WebSocket 实时推送。
- 消息、讨论、统计数据 Excel 导出。
- 离线阅读已缓存消息。
- 离线发布草稿, 联网后同步。

验收标准:

- 推送开关、权限、频率可控。
- 导出数据字段明确且权限正确。
- 离线能力不影响在线主流程。

### 迭代 5: AI投顾与专业版能力

目标: 在稳定基础上增强产品价值。

候选任务:

- 智能选股助手。
- 投资组合分析。
- 风险评估工具。
- 个性化推荐。
- AI配置导出/导入。

验收标准:

- AI功能有明确免责声明和合规边界。
- 关键输出有评估样例和人工验收标准。
- 用户数据隔离不被破坏。
