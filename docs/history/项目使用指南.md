## 📋 项目背景

### 项目概述

VIP投研内部分享系统是一个面向内部用户的私密投研分享平台，管理员可以向指定分组的用户群发推送投研消息，用户可以查看历史消息并发起讨论。系统支持讨论内容的可见性控制，确保信息安全和隐私保护。

- [项目迭代记录.md](./项目迭代记录.md) - 项目优化迭代历史

### 项目目的

1. **高效信息推送**
   - 管理员可以快速向指定分组推送投研消息
   - 支持图片和文字混合内容
   - 支持消息类型和标签分类

2. **便捷信息查看**
   - 用户可以方便地查看自己收到的消息
   - 支持搜索功能和按日期查看
   - 支持消息收藏和标记已读

3. **互动讨论功能**
   - 用户可以就消息发起讨论
   - 讨论内容可以设置为公开或私密
   - 管理员可以控制讨论可见性

4. **用户权限管理**
   - 支持多种用户角色（超级管理员、管理员、VIP用户、体验用户）
   - 支持用户分组管理
   - 支持用户状态管理

### 项目特点

- **前后端分离架构**：前端使用Vue 3 + uni-app，后端使用Node.js + Express
- **响应式设计**：支持PC和移动端访问
- **金融科技风格**：深色主题，玻璃态效果，专业美观
- **自动化部署**：支持一键部署到云服务器
- **版本控制**：支持Git版本管理和快速回滚
- **多端支持**：支持H5和小程序部署

## 🚀 快速开始

### 环境要求

- **操作系统**：Windows 10/11
- **Node.js**：v20.20.0+
- **Git**：最新版本
- **MySQL**：5.7.0+（本地开发可选）
- **PowerShell**：5.1+（推荐7+）

### 安装步骤

#### 1. 克隆项目

```bash
cd d:\your-mcp-proxy\AITY_VIP
```

#### 2. 安装依赖

**安装后端依赖：**
```bash
cd backend
npm install
```

**安装前端依赖（uni-app项目）：**
```bash
cd ../aity-uni-app-new
npm install
```

#### 3. 配置环境

**创建环境配置文件：**
```bash
cd backend
copy .env.example .env
```

**编辑.env文件，配置数据库连接：**
```env
# 数据库配置
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_database_password
DB_NAME=private_sharing_app

# JWT配置
JWT_SECRET=your-secret-key
JWT_EXPIRES_IN=24h

# 服务器配置
PORT=3001
```

#### 4. 初始化数据库

```bash
# 登录MySQL
mysql -u root -p

# 创建数据库
CREATE DATABASE private_sharing_app;

# 导入数据库脚本
USE private_sharing_app;
SOURCE d:/your-mcp-proxy/AITY_VIP/database.sql;
```

#### 5. 启动服务

**启动后端服务：**
```bash
cd backend
npm start
```

**启动前端服务（H5）：**
```bash
cd ../aity-uni-app-new
npm run dev:h5
```

**启动前端服务（微信小程序）：**
```bash
cd ../aity-uni-app-new
npm run dev:mp-weixin
```

#### 6. 访问应用

- **H5端**：http://localhost:5173
- **后端API**：http://localhost:3001/api/health

## 🔧 常见问题

### 1. 端口冲突

**问题**：启动后端时提示端口被占用

**解决方案**：
```bash
# 查找占用端口的进程
netstat -ano | findstr :3001

# 杀掉占用端口的进程
taskkill /PID <进程ID> /F
```

### 2. 数据库连接失败

**问题**：后端无法连接到数据库

**解决方案**：
- 检查MySQL服务是否启动
- 检查.env文件中的数据库配置
- 检查数据库用户名和密码是否正确

### 3. SSH连接失败

**问题**：无法连接到云服务器

**解决方案**：
- 检查网络连接
- 检查SSH密钥配置
- 检查云服务器安全组设置

详见[SSH密钥管理方案.md](./SSH密钥管理方案.md)

### 4. 部署脚本执行失败

**问题**：PowerShell脚本执行失败

**解决方案**：
- 使用英文版本脚本（推荐）
- 或安装PowerShell 7+：`winget install Microsoft.PowerShell`
- 或在PowerShell ISE中运行

详见[部署指南.md](./部署指南.md)

### 5. 中文脚本乱码

**问题**：中文版本脚本运行时出现乱码

**解决方案**：
- 使用英文版本脚本（推荐）
- 或在PowerShell 7+中运行：`pwsh ./scripts/部署_CN.ps1`
- 或在PowerShell ISE中运行

### 6. uni-app构建失败

**问题**：构建小程序时失败

**解决方案**：
- 检查依赖是否安装正确
- 检查pages.json配置是否正确
- 检查是否使用了小程序不支持的API

## 📚 最佳实践

### 代码规范

#### 前端代码

1. **Vue组件规范**
   - 使用Composition API
   - 组件命名使用PascalCase
   - 添加必要的注释
   - 使用uni-app组件确保多端兼容

2. **CSS规范**
   - 使用SCSS预处理器
   - 保持样式简洁
   - 避免内联样式
   - 使用变量管理颜色和尺寸

3. **JavaScript规范**
   - 使用ES6+语法
   - 函数命名清晰
   - 添加错误处理
   - 使用async/await处理异步操作

#### 后端代码

1. **目录结构**
   - 按功能模块划分目录
   - 保持目录结构清晰
   - 避免循环依赖

2. **代码风格**
   - 使用一致的代码风格
   - 添加必要的注释
   - 遵循单一职责原则

3. **错误处理**
   - 捕获所有可能的错误
   - 返回清晰的错误信息
   - 记录错误日志

### 版本管理

#### 分支策略

**推荐分支策略：**
- **main分支**：生产环境分支，保持稳定
- **develop分支**：开发环境分支，日常开发
- **feature分支**：开发新功能，从develop分支创建
- **fix分支**：修复Bug，从develop分支创建
- **hotfix分支**：紧急修复，从main分支创建

**详细说明：**
详见 [Git分支管理规范.md](./Git分支管理规范.md)

#### 分支操作

**查看分支：**
```bash
git branch -a
```

**创建新分支：**
```bash
git checkout -b feature/new-feature
```

**切换分支：**
```bash
git checkout develop
```

**删除分支：**
```bash
git branch -d feature/new-feature
```

**合并分支：**
```bash
git merge feature/new-feature --no-ff
```

#### 提交规范

1. **提交信息格式**
   ```
   <type>(<scope>): <subject>

   <body>
   ```

2. **类型说明**
   - `feat`: 新功能
   - `fix`: 修复bug
   - `docs`: 文档更新
   - `style`: 代码格式调整
   - `refactor`: 代码重构
   - `perf`: 性能优化
   - `test`: 测试相关
   - `chore`: 构建/工具相关

3. **示例**
   ```
   feat(auth): 添加用户登录功能

   - 实现邮箱和用户名双重登录
   - 添加Token管理
   - 添加登录状态持久化

   Closes #1
   ```

#### 1. 密码管理

- 不要在代码中硬编码密码
- 使用环境变量存储敏感信息
- 定期更换密码

#### 2. 数据加密

- 使用HTTPS加密传输
- 使用JWT保护API
- 加密存储敏感数据

#### 3. 权限控制

- 实现基于角色的访问控制
- 验证用户权限
- 记录操作日志

- 使用CDN加速资源加载
- 压缩和合并静态资源
- 使用懒加载

- 优化SQL查询
- 使用连接池
- 实现API限流
