# 2026-08-10 小程序发布入口与表单布局优化

## 一、背景

在上一轮小程序 UI 走查基础上，继续处理消息筛选重置不完整、悬浮发布按钮容易误拖动，以及发布页底部操作栏在不同屏幕和权限状态下遮挡内容的问题。

## 二、本次变更

### 1. 消息筛选

- 点击“重置”时，同时恢复消息类型、推送范围和阅读状态。
- 用户从“未读”模式重置后会回到“全部”，避免界面条件已清空但列表仍只显示未读。

### 2. 消息与交流发布入口

- 移除消息页发布按钮的任意拖拽逻辑，恢复为明确的单击发布入口。
- 消息页和交流页发布按钮统一固定在内容区右下角。
- 按钮位置同时避开底部 TabBar 和设备安全区，减少遮挡及误操作。

### 3. 消息发布页

- 删除基于固定 `140rpx` 底栏高度计算滚动区域的逻辑。
- 表单滚动区域跟随页面容器，使用底部占位避开实际固定操作栏。
- 底部占位使用最小高度，兼容管理员邮件提醒区显示与普通编辑状态。

### 4. TabBar 图标判断

- 当前项目静态资源只有 `logo.png`，没有四组适配原生 TabBar 的普通态和选中态 PNG 图标。
- 本次不使用临时字符或不一致图标，待形成完整图标资源后单独接入。

## 三、自动验证

在 `aity-uni-app-v2` 目录执行：

```powershell
npm run verify:mp-weixin
```

验证内容包括：

- 讨论关联消息测试；
- 小程序 UI 结构契约测试；
- 微信小程序生产构建。

构建产物：`dist/build/mp-weixin`。

H5 构建本轮未通过：当前本机 `node_modules` 缺少 `vue-router/dist/vue-router.esm-bundler.js`，失败发生在依赖解析阶段，与本轮页面样式改动无关；微信小程序构建不受影响。后续需要专门恢复完整依赖后再补做 H5 构建。

## 四、人工验收重点

- 消息中心切换到“未读”，展开筛选并点击“重置”，确认列表和快捷状态都回到“全部”。
- 管理员点击消息页右下角加号，确认直接进入发布页且按钮不再被拖动。
- 点击交流页右下角加号，确认直接进入发起交流页。
- 在有底部安全区和无底部安全区的设备上，确认两个发布按钮均不遮挡 TabBar。
- 在消息发布页滚动到最后一项，确认内容、邮件提醒开关和发布按钮均可操作；唤起键盘后页面仍可滚动。

## 五、发布影响

- 本次仅修改共用前端源码，不涉及后端接口、数据库和腾讯云后端部署。
- 微信小程序需要重新上传构建产物并发布新版本，用户才能看到本次优化。
- H5 与小程序共用源码，提交前同步执行 H5 构建检查。
