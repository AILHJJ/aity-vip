# AITY VIP 持续迭代维护 SOP

> 更新时间：2026-08-08
> 目标读者：产品、开发、测试、运维
> 目的：把 AITY VIP 后续小程序、H5、后端迭代固定到可复现流程，减少目录混乱、无关提交和发布不可追溯。

## 为什么现在要做

当前项目已经形成干净基线 `AITY_VIP_iteration_current`，但历史目录中存在旧 H5 源码、服务器快照、归档文档、敏感配置和临时产物。后续如果继续按聊天记录或临时目录推进，很容易再次出现无法判断线上版本、构建脚本失效、提交混杂的问题。

## 推荐结论

| 事项 | 推荐做法 |
| --- | --- |
| 前端维护 | 一套 `aity-uni-app-v2` 源码，同时构建小程序和 H5 |
| 小程序发布 | 本地构建后用微信开发者工具或 `miniprogram-ci` 上传 |
| H5 发布 | 本地构建后上传 `dist/build/h5/` 到服务器静态目录 |
| 后端发布 | Git/SHA 可追踪部署，运行态配置留在服务器 |
| 需求开发 | 一个工作项一个短生命周期分支 |
| 验证 | 按 `.tdx/impact.json` 命中模块执行对应命令 |

## 标准流程

| 阶段 | 操作 | 输出 |
| --- | --- | --- |
| 1. 立项 | 写清目标、范围、不做事项、验收标准 | 工作项说明 |
| 2. 建分支 | `feat/AITY-YYYYMMDD-topic` 或正式工单编号 | 短生命周期分支 |
| 3. 影响分析 | 对照 `.tdx/impact.json` 搜索调用方和消费者 | 影响范围和验证命令 |
| 4. 小步开发 | 前端、后端、迁移分开处理，避免混入重构 | 原子提交 |
| 5. 验证 | 小程序/H5/后端按影响执行构建或测试 | 可复现验证结果 |
| 6. 发布 | 小程序走微信工具，H5 走静态产物，后端走 Git/SHA | 发布记录 |
| 7. 回滚 | 小程序回退版本，H5 恢复备份目录，后端回退提交或 PM2 配置 | 回滚记录 |

## 前端迭代规则

| 改动类型 | 必跑验证 | 是否需要服务器 |
| --- | --- | --- |
| 小程序页面/样式 | `npm run build:mp-weixin` | 否 |
| H5 适配 | `npm run build:h5` | 仅发布 H5 产物时需要 |
| API 调用字段 | 小程序构建 + 后端接口验证 | 如后端变化则需要 |
| 登录/鉴权/上传 | 小程序构建 + 手工真机/开发者工具验证 | 可能需要 |

## 后端迭代规则

| 改动类型 | 要求 |
| --- | --- |
| 新增 API | 先定义请求/响应和兼容策略，再改前端调用 |
| 数据库迁移 | 先扩展、再切换、最后收缩；写回滚说明 |
| 上传/文件 | 不把 `uploads/` 进 Git，发布时保留服务器运行态数据 |
| 配置/密钥 | 只维护 `.env.example`，真实值留在服务器或密钥系统 |

## 固化脚本入口

| 场景 | 推荐命令 | 说明 |
| --- | --- | --- |
| 构建微信小程序 | `.\scripts\一键构建微信小程序.ps1` | 输出到 `aity-uni-app-v2/dist/build/mp-weixin` |
| 查看腾讯云后端状态 | `.\scripts\检查腾讯云后端状态.ps1` | 只读检查 current、PM2、health、邮件提醒状态 |
| 准备后端 release | `.\scripts\一键发布腾讯云后端.ps1` | 测试、打包、上传、prepare，不切换线上 |
| 发布后端到线上 | `.\scripts\一键发布腾讯云后端.ps1 -Switch` | 包含 PM2 重启，属于生产动作 |
| 回滚后端 | `.\scripts\一键发布腾讯云后端.ps1 -Rollback -RollbackVersion <版本号>` | 切回指定 release |

## 提交说明模板

```text
<type>(<scope>): <result>

Context:
- 为什么需要这次改动

Behavior:
- 关键行为变化
- 明确不变的边界

Verification:
- 命令或步骤: passed/failed/未执行原因

Risk:
- 风险和回滚方式
```

## 待确认问题

| 问题 | 影响 | 建议处理 |
| --- | --- | --- |
| 是否配置正式远端仓库 | 决定后续 MR/PR 和服务器 Git 部署方式 | 确认后设置 remote |
| 小程序是否启用 `miniprogram-ci` | 决定是否自动上传体验版 | 暂先用微信开发者工具 |
| 后端测试库是否可固定 | 决定 `npm test` 是否成为强门禁 | 补测试库配置和测试账号 |
| 邮件服务商 | 影响通知推送一期实现 | 优先确认 SMTP/腾讯云 SES/企业邮箱 |

## 落地拆解

| 阶段/任务 | 交付物 | 验收方式 |
| --- | --- | --- |
| 1. 规则接入 | `AGENTS.md`、`.tdx/impact.json`、本 SOP | 新需求开始前能按文件执行 |
| 2. 推送一期 | 邮件 outbox、发送服务、发送日志 | 发布消息后可异步发送邮件 |
| 3. 小程序入口 | 通知设置/消息提醒入口 | 小程序构建和体验版验证通过 |
| 4. H5 跟随适配 | 同源码 H5 构建产物 | `npm run build:h5` 通过并可部署 |
| 5. 发布可观测 | 后端 health/build 信息、前端版本记录 | 能追溯版本、时间和提交 |
