## 日常检查与发布

在日常维护目录`D:\your-mcp-proxy\99-个人探索\AITY_VIP_iteration_current`执行，使用已适配新机的脚本：

```powershell
.\scripts\迁移服务器检查.ps1 -Action status
.\scripts\检查腾讯云后端状态.ps1
.\scripts\检查SSL证书状态.ps1
# 已提交代码生成制品并准备新版本，暂不切换
.\scripts\一键发布腾讯云后端.ps1 -RequireClean
# 获得对应版本的验证证据后再切换
.\scripts\腾讯云后端发布管理.ps1 -Action switch -Version <提交号>
# 回退上一次成功切换前的代码；保留当前数据库
.\scripts\腾讯云后端发布管理.ps1 -Action rollback
```

AITY发布脚本默认使用新IP、ubuntu及本机迁移专用密钥，制品仍保存于项目`deploy/releases/<提交号>/`，检查SHA256、发布锁、版本目录和健康状态。已存在目录不直接删除重建。切换健康失败会恢复切换前代码；不能把代码回滚当成数据库迁移回滚。数据库结构变更须单独设计兼容性和恢复方案。

AI体验广场独立项目为 `D:\your-mcp-proxy\99-个人探索\ai-experience-mini-impl`。该项目的 `scripts/管理腾讯云发布.ps1` 和 `deploy/release.sh` 已改用新机及Caddy；新机 `/root/ai-expo/manage.sh` 与其一致。`status/prepare/preflight/switch/rollback`沿用原流程，业务发布不改共享网关。两个项目应分别提交与发布，不把AI体验广场代码推送到AITY仓库。

新机首次迁移只恢复了当时的当前生产release。历史release源码另存保护归档；上一次版本回滚指针在下一次成功发布后生成，不能假定旧机上的全部历史版本已安装依赖、可直接运行。

## 域名与证书

域名解析由原持有账号的DNSPod管理，与旧服务器是否到期无关。以后修改解析不需SSH登录旧服务器；继续保留域名账号和域名续费。域名/小程序AppID不变时，无需仅为IP变化修改微信合法域名。

主域名、www、ha、openclaw及原有`_dnsauth`的A记录已切到新IP；验证TXT记录保留。`_dnsauth`只是历史域名验证主机名，不是单独业务网站。缓存未刷新时仍可能访问旧地址，客户端完成刷新后不依赖旧机转发。

另增加`claw.aity88.online`备用管理入口：本机网络访问原openclaw域名出现TLS重置，服务器间验证正常；备用域名指向相同服务和数据，不重新创建OpenClaw账号。两个来源均明确列入原控制台的允许来源，原有鉴权和设备配对保留。

备用入口已从本机验证HTTPS 200及WebSocket连接成功。浏览器新域名的本地存储独立，首次访问可能需重新填入原网关令牌或确认设备配对；令牌只从新机root私有配置取得，不写入文档或URL。

证书位于`/etc/caddy/tls/`，由新机`/root/.acme.sh`维护，HTTP验证目录为`/var/www/html`。续期服务`aity-cert-renew.service`检查全部证书，`aity-cert-renew.timer`每日北京时间04:15加随机延迟执行。重载命令使用Caddy。当前手工续期检查成功，但尚未到实际续签日期，不能据此声称已经完成一次真实自动续签。

HA原有每30分钟巡检已迁入`ha-health-check.timer`，脚本和告警密钥保留在root私有目录，正常时静默。没有复制宝塔的数据库重启任务、过期Nginx续期任务或旧系统云agent任务到新机。

迁移完成后的最新恢复包为`/root/aity-migration/live-20261112T144829Z`，本机保护目录中有同名副本，均已核验SHA256。包含新网关及全部证书/续期配置、三库逻辑备份、HA SQLite备份及当前服务配置；恢复时优先区分这个新机快照和较早的旧机快照。

## 每日自动备份

新机已启用`aity-backup.timer`：每天北京时间04:45起随机延迟最多10分钟执行，停机错过后补执行。备份无需人工每天运行。`aity-backup.service`首次实际执行成功；服务为一次性任务，成功后显示inactive/dead属于正常状态，应检查Result和ExecMainStatus。

备份位置`/root/aity-backups/live-<UTC时间戳>/`，仅root可读。脚本通过文件锁防止并发，成功完成后保留最近7个完整快照，不清理迁移保护归档；可用空间低于1GiB时拒绝开始。失败目录保留用于排查，不计入成功快照，需维护人及时检查，避免长期积累。

| 文件 | 内容及边界 |
| --- | --- |
| `databases.sql.gz` | 三个MySQL数据库的事务逻辑备份，含表结构及数据 |
| `home-assistant.sqlite` | SQLite在线备份，已执行quick_check |
| `configuration.tar.gz` | 业务环境、Caddy/证书/acme、OpenClaw/HA配置及相关系统服务 |
| `applications.tar.gz` | 当前两套release源码、H5和共享上传文件；排除node_modules、Git及日志 |
| `manifest.json` | 数据库名、当时release路径、文件大小和SHA256；最后生成，表示本次备份完成 |
| `verification.json` | 手工运行隔离恢复验证后生成的结果；每日备份不会自动创建临时数据库 |

```bash
# 在新机通过sudo执行；这些命令不切换线上版本
sudo systemctl list-timers aity-backup.timer --no-pager
sudo systemctl show aity-backup.service -p Result -p ExecMainStatus
sudo journalctl -u aity-backup.service -n 20 --no-pager
# 需要额外备份时调用已安装脚本；不带--daily，保存到迁移保护目录且不自动清理
sudo python3 /root/aity-migration/runtime/backup-live-config.py
# 验证指定快照：先校验文件，再用受限账号恢复到随机临时库，最后清理
sudo python3 /root/aity-migration/runtime/verify-live-backup.py /root/aity-backups/live-20261112T150156Z
```

每日快照约105MiB，当前7份约735MiB，实际随用户内容增长。它是同机备份，不覆盖整机磁盘丢失；迁移当天及首次每日快照已下载到本机保护目录。持续异机备份仍需确定对象存储或另一台备份主机及授权，未假定已经自动异地同步。

归档不包含操作系统镜像、Docker镜像层、语音模型及OpenClaw精确版本依赖；这些从迁移保护归档和已记录的固定版本恢复。数据库与文件分别在线采集，不能将其理解为全系统同一时刻的原子快照。

## 故障恢复顺序

1. 代码故障优先用发布脚本回退上一次release，保留数据库，不直接恢复旧数据。当前迁移基线尚无自动生成的上一版本指针，先核对可运行release。
2. 若需要数据恢复，先停止受影响业务的写入和邮件消费，另做故障现场备份；核对快照时间、manifest、SHA256与隔离恢复报告。恢复数据会丢弃快照后的变化，先由维护人确定增量处理方式。
3. 在独立目标恢复MySQL逻辑备份和上传文件；HA停止后再恢复SQLite及对应配置。禁止将原SQL直接导入仍在服务的生产库，禁止向根目录整包覆盖系统。
4. 恢复当前release与shared软链，依锁文件重建Node依赖；OpenClaw、语音服务按迁移记录中的精确版本恢复。使用新机Caddy配置，保留Hermes及SSH入口。
5. 验证接口鉴权、消息/讨论、图片、H5、SMTP认证及必要的真机操作，最后恢复写入。整机灾难重建、生产数据库覆盖恢复及服务器回迁尚未演练，不能称为一键无损恢复。

仅需撤销本轮新增自动备份时运行`sudo systemctl disable --now aity-backup.timer`；若备份正在执行，让其完成后再维护脚本。不要删除已有快照，不需重启业务或修改DNS。
