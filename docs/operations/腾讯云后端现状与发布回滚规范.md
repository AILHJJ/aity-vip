- 本地发布包已按版本放入项目内 `deploy/releases/<版本号>/`

- `backend.env` 已迁移到 `/root/aity-vip/shared/backend.env`

## 二、这意味着什么

### 直接覆盖方式

如果把新包直接解压到 `/root/aity-vip/backend`：

- 会立即影响线上服务
- 部署最简单
- 回滚最麻烦，只能依赖备份目录或重新覆盖旧包

### 标准化方式

推荐改成：

- `/root/aity-vip/releases/<版本号>` 保存每次发布包
- `/root/aity-vip/current` 软链指向当前版本
- PM2 启动 `current/backend/src/index.js`
- 回滚时只切换软链

这样可以做到：

- 版本可追溯
- 回滚简单
- 日常迭代更稳

## 三、邮件配置是否需要额外操作

需要。

仅修改代码不够，部署时还要在服务器 `backend/.env` 中补齐邮件配置，否则 PM2 进程还是旧环境变量。

线上后端代码在 `NODE_ENV=production` 时优先加载：

1. `/root/aity-vip/backend/.env.production`
2. 找不到 `.env.production` 时，才回退加载 `/root/aity-vip/backend/.env`

因此当前生产环境邮件配置应优先写入 `.env.production`。如果后续迁移到 `releases/current`，建议把真实配置集中放在 `/root/aity-vip/shared/backend.env`，再软链到当前 release 的 `backend/.env.production`。

```env
MAIL_ENABLED=true
MAIL_DRY_RUN=true
MAIL_AUTO_PROCESS=true
MAIL_NOTIFY_ADMINS=false
MAIL_NOTIFY_COOLDOWN_MINUTES=10
BUSINESS_TIMEZONE_OFFSET_MINUTES=480
NOTIFICATION_OUTBOX_AUTO_SYNC=true
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=lhdms88@163.com
SMTP_PASS=163邮箱客户端授权码
MAIL_FROM_NAME=AITY投研提醒
MAIL_FROM=lhdms88@163.com
```

说明：

- `SMTP_PASS` 必须是 163 邮箱客户端授权码，不是登录密码
- 首次上线建议先 `MAIL_DRY_RUN=true`
- 确认 `notification_outbox` 正常后，再切到 `false`
- `MAIL_NOTIFY_COOLDOWN_MINUTES` 控制邮件提醒冷却期，默认建议 `10`
- `BUSINESS_TIMEZONE_OFFSET_MINUTES=480` 表示按北京时间修正邮件提醒时间，避免 MySQL `DATETIME` 被 JS 当成 UTC 后出现 400 多分钟剩余等待
- 邮件正文只能提示“小程序有更新”，不得包含消息标题、摘要、股票、观点或具体投研内容
- 冷却期内管理员仍可在小程序弹窗中确认继续发送，后端通过 `emailNotifyForce=true` 记录本次人为覆盖

## 四、推荐发布流程

### 方案 A：当前可用的临时方式

适合当前服务器仍是直接运行目录时：

1. 本地生成后端发布包
2. 服务器备份 `/root/aity-vip/backend`
3. 解压覆盖到 `/root/aity-vip/backend`
4. 更新 `backend/.env`
5. `pm2 restart aity-backend --update-env`
6. 查看 `pm2 status aity-backend`

### 方案 B：后续标准方式

1. 每次发布生成一个版本目录
2. `current` 软链指向当前版本
3. PM2 只认软链入口
4. 回滚直接切换软链

## 五、回滚规范

### 当前临时方式回滚

如果这次发布有问题：

1. 找到备份目录
2. 还原 `/root/aity-vip/backend`
3. 恢复原 `.env`
4. `pm2 restart aity-backend --update-env`

### 标准方式回滚

如果改成 `releases/current`：

1. 切换 `current` 软链到上一个版本
2. `pm2 restart aity-backend --update-env`
