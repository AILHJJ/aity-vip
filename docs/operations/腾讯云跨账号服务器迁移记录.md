## 后续执行顺序

1. 先在旧机备份两个业务数据库、上传文件、线上 release、H5、私密环境配置、Nginx 和证书/续期任务，并复制到旧机之外。数据库备份校验 SHA256，并测试恢复；备份本身含敏感业务信息，严格限制权限，不提交 Git。
2. MySQL 5.7 到新环境需做逻辑导出和恢复验证；不复制运行中的原始数据目录。确认目标版本、字符集/排序规则、SQL mode、视图/触发器/事件及应用驱动兼容性，不直接重建业务数据。
3. 新机保留现有服务，用系统 Node 22 部署当前线上两个 release，沿用 releases/current/shared；迁移时不混入新功能。
4. 私密环境通过加密通道传输；保留 JWT 和业务加密密钥。AITY 的实际生产加载文件应核对 `.env.production` 与 shared/backend.env 软链；不要仅写 `.env` 后假定生效。
5. 新机邮件队列消费者、定时发送和其他后台写任务先关闭。核对 Caddy 是否承担 Hermes 入口后，再决定迁移网关配置；不能直接并行启动另一个占用 80/443 的 Nginx。
6. 使用本地 hosts 或 curl --resolve 在不切 DNS 时验证原域名路由、HTTPS、图片、H5、API、WebSocket 和真实登录。证书与续期机制需独立验收。
7. 最终切换前暂停旧站写入和队列消费，最终同步两库和图片，验证后切换 DNS。DNS 传播期间旧入口维护或转发，不能让两个数据库分别接收业务写入。
8. 切换前可直接放弃新机部署。切换后若新机已产生业务写入，回滚必须处理新增数据；不能只切 DNS 回旧数据库。保留旧机与备份，记录切换时间、版本、校验结果和回滚操作。

域名与小程序 AppID 保持不变；跨实名认证主体的备案资源使用及接入信息要求仍需由腾讯云根据实际主体确认。本轮未改域名解析、备案、微信后台或线上服务配置。
