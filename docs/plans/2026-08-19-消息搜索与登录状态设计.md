# 消息搜索与登录状态设计

## 背景

当前消息页的搜索逻辑只过滤前端已经加载到内存中的消息。用户滚动加载之前的历史消息不会参与搜索，无法满足按历史内容查找消息的需求。

当前线上 JWT 有效期为 7 天。JWT 无效或过期时，后端鉴权中间件返回 HTTP 403，小程序将其按普通权限错误处理，用户不会得到明确的重新登录引导。

## 目标

1. 在用户有权限查看的消息范围内，支持按标题和正文进行后端分页搜索。
2. 保留角色权限、发布状态、未读状态、消息类型和推送范围过滤。
3. JWT 无效或过期时使用 HTTP 401 表达认证失效。
4. 小程序只提示一次登录状态过期，并清理本地登录状态后跳转登录页。
5. 用户账号到期或被停用继续使用独立的业务提示，不与 JWT 过期混淆。

## 方案

### 消息搜索

- `GET /api/messages` 增加可选参数 `keyword`。
- 后端在 `title` 和 `content` 上使用包含匹配，并与现有可见性条件通过 `AND` 组合。
- 搜索结果仍由后端分页，前端不再对关键词做本地二次过滤。
- 小程序在点击搜索、键盘确认、选择搜索历史或清空关键词时重新请求第 1 页。
- 不在每次输入字符时发起网络请求，避免小程序产生大量请求。

### 登录状态

- 鉴权中间件对“缺少 Token”保持 HTTP 401。
- 对“Token 无效或过期”改为 HTTP 401。
- 对“用户不存在”保持 HTTP 401。
- 对“账号已到期/被停用”保持 HTTP 403，并保留中文业务提示。
- 小程序收到非登录请求的 401 后清理 `token`、`userInfo` 和 `unreadCount`，显示“登录状态已过期，请重新登录”，延迟跳转登录页。
- 使用一次性处理标记，避免多个并发请求重复弹出提示或重复跳转。

## 不在本次范围内

- 不一次性加载全部历史消息。
- 不改变消息角色权限规则。
- 不改变线上 JWT 的 7 天有效期。
- 不修改账号延期、停用和自动过期策略。
- 不修改 H5 独立代码；H5 与小程序共用同一套 uni-app 源码。

## 验收标准

- 关键词可以检索当前页面尚未加载的历史消息，并正确返回分页总数。
- 无关键词时现有消息列表行为不变。
- 无效 JWT 请求返回 HTTP 401。
- 小程序遇到 JWT 401 时本地登录状态被清理，并进入登录页。
- 账号业务到期仍提示联系管理员续期，不显示“登录已过期”。
- 后端语法检查、受影响单元测试、前端契约测试和微信小程序生产构建通过。
