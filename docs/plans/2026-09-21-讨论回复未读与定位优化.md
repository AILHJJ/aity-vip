# 讨论回复未读与定位优化方案

> 日期：2026-09-21
> 背景：用户反馈——自己发的帖子被管理员回复后，帖子较多时不知道最新回复是哪条、哪些需要查看。

## 一、问题与根因

| 层级 | 现状 | 断点 |
|---|---|---|
| 入口层 | 全局未读数（tab 红点） | 只知道"有回复"，不知是哪些帖 |
| 列表层 | status 二态徽标 + 回复总数 | 无"新增"标识，不按最新回复排序 |
| 详情层 | 回复时间平铺 | 无新回复高亮/定位，管理员回复无区分 |

## 二、方案

### 数据模型
- 新增 `discussion_reads` 表：`user_id + discussion_id + last_seen_at`（帖级已读时间）
- `discussions` 加冗余列 `last_reply_at`（最后回复时间，用于列表排序）

### 后端接口
1. `getMyDiscussions`：返回每帖 `unreadCount`、`lastReplyAt`、`lastReplyUserName`、`lastReplyContent`（摘要）；按 `last_reply_at DESC` 排序；支持 `?filter=unread`
2. `getDiscussionById`：每条 reply 返回 `isNew`（晚于 last_seen_at）、`isAdminReply`；返回帖级 `unreadCount`
3. `POST /discussions/:id/read`：标记该帖已读（upsert discussion_reads）
4. `addDiscussionReply`：更新 `last_reply_at = now`

### 前端
- 我的讨论列表：🔴 N 新角标 + 回复摘要预览 + 「只看新回复」筛选
- 讨论详情：新回复高亮 + 自动定位 + 管理员「官方回复」徽标 + 进入标记已读

## 三、管理员识别
回复者 role 为 `super_admin`/`admin` 判定为管理员回复。
