## 🔍 方案详解

### 1. API测试（最推荐）

#### 适用场景
- 后端接口功能验证
- 快速回归测试
- CI/CD流水线集成

#### 优点
- 执行速度极快（毫秒级）
- 稳定性最高
- 无需额外工具
- 容易调试

#### 缺点
- 无法测试前端UI
- 无法验证用户体验

#### 使用示例
```bash
# 健康检查
curl http://localhost:3001/api/health

# 登录测试
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"admin123"}'

# 批量测试脚本
bash tests/api/api-quick-test.sh
```

#### 结论
**强烈推荐**，作为所有测试的基础，优先验证后端功能。

---

### 2. Playwright（最推荐 - H5测试）

#### 适用场景
- H5网页端到端测试
- 多浏览器兼容性测试
- 自动化回归测试

#### 优点
- 业界主流框架，生态完善
- 支持多浏览器（Chromium, Firefox, WebKit）
- 调试体验优秀
- 文档和社区完善

#### 缺点
- 首次需要下载浏览器（约300MB）
- 需要编写维护测试代码

#### 使用示例
```bash
# 安装
npm install -D @playwright/test
npx playwright install

# 运行测试
npx playwright test

# 带界面调试
npx playwright test --headed

# 查看报告
npx playwright show-report
```

#### 测试代码示例
```javascript
const { test, expect } = require('@playwright/test');

test('用户登录', async ({ page }) => {
  await page.goto('http://localhost:5173/#/pages/login/login');
  await page.fill('input[type="text"]', 'admin@example.com');
  await page.fill('input[type="password"]', 'admin123');
  await page.click('button[type="submit"]');
  await expect(page).toHaveURL(/.*index/);
});
```

#### 结论
**强烈推荐**，H5测试首选方案。

### 3. uni-automator（小程序测试首选）

#### 适用场景
- 微信小程序自动化测试
- 小程序特有API测试

#### 优点
- uni-app官方支持
- 完美适配项目
- 支持真机测试

#### 缺点
- 依赖微信开发者工具
- 稳定性依赖工具状态
- 编译+执行较慢（约20秒）

#### 使用示例
```bash
# 前提：开启微信开发者工具服务端口

# 运行测试
npx uni-automator test --platform mp-weixin

# 或使用脚本
node tests/miniprogram/automated-test.js
```

#### 测试代码示例
```javascript
const { Automator } = require('@dcloudio/uni-automator');

describe('小程序测试', () => {
  let miniProgram;

  before(async () => {
    miniProgram = await Automator.launch({
      projectPath: './dist/dev/mp-weixin',
      cliPath: 'C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat'
    });
  });

  it('登录测试', async () => {
    const page = await miniProgram.reLaunch('/pages/login/login');
    await page.waitFor(1000);
    // 测试逻辑
  });
});
```

#### 结论
**推荐**，小程序测试首选方案。

### 4. Dev Browser（强烈推荐 - H5测试）

Dev Browser 是一个基于 Playwright 的浏览器自动化测试工具，支持两种运行模式。

#### 两种运行模式对比

| 模式 | 命令 | 浏览器来源 | 需要扩展 | 登录态 |
|------|------|-----------|---------|--------|
| **Standalone** | `./server.sh` | 启动新浏览器 | ❌ 不需要 | 独立（需重新登录） |
| **Extension** | `npm run start-extension` | 复用用户浏览器 | ✅ 需要 | 共享（复用已有登录） |

---

#### Standalone 模式（推荐）

**优点**：
- ✅ 配置简单，开箱即用
- ✅ 稳定性高，独立浏览器进程
- ✅ 环境干净，每次全新环境
- ✅ 支持持久化 Profile
- ✅ 适合 CI/CD，支持 headless 模式

**缺点**：
- ❌ 需要重新登录
- ❌ 资源占用较高（约200-400MB）
- ❌ 需指定 Chrome 路径

**使用示例**：
```bash
# 1. 设置 Chrome 路径（Windows）
set CHROME_PATH=D:\your-mcp-proxy\AITY_VIP\chrome-win64\chrome.exe

# 2. 启动服务器
cd ~/.claude/skills/dev-browser
./server.sh

# 3. 运行测试
npx tsx tmp/my-test.ts
```

---

#### Extension 模式

**优点**：
- ✅ 复用登录态，无需重复登录
- ✅ 真实用户环境
- ✅ 零额外资源占用
- ✅ 适合调试和快速验证

**缺点**：
- ❌ 需要安装浏览器扩展
- ❌ 只能一个浏览器连接
- ❌ 用户操作可能干扰测试

**使用示例**：
```bash
# 1. 安装扩展到 Chrome/Edge
#    访问 chrome://extensions/
#    开启开发者模式，加载扩展目录

# 2. 启动 Extension 服务器
cd ~/.claude/skills/dev-browser
npm run start-extension

# 3. 运行测试（确保只有一个浏览器连接）
npx tsx tmp/my-test.ts
```

---

#### 模式选择建议

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 自动化测试/CI/CD | **Standalone** | 稳定、可重复、无需扩展 |
| 测试登录功能 | **Standalone** | 环境干净，便于测试登录流程 |
| 测试已登录功能 | **Extension** | 复用登录态，省去登录步骤 |
| 企业内网/SSO | **Extension** | 复用复杂的SSO登录状态 |
| 快速调试 | **Extension** | 连接即用，无需等待 |
| 多实例并行测试 | **Standalone** | 可同时运行多个实例 |

---

#### 测试代码示例
```typescript
import { connect, waitForPageLoad } from "@/client.js";

async function test() {
  const client = await connect();
  const page = await client.page("test-page", {
    viewport: { width: 1920, height: 1080 }
  });

  await page.goto("http://localhost:5173");
  await waitForPageLoad(page);

  // 截图
  await page.screenshot({ path: "tmp/screenshot.png" });

  await client.disconnect();
}

test().catch(console.error);
```

#### 结论
**强烈推荐**，H5测试优秀方案。Standalone 模式稳定可靠，Extension 模式方便复用登录态。

### 5. Playwright Skill（探索方案）

#### 适用场景
- AI自动生成测试代码
- 快速创建测试用例

#### 优点
- 自动生成代码
- 符合最佳实践
- 减少手动编写

#### 缺点
- 需要LLM API
- 生成代码可能需要调整
- 复杂场景效果一般

#### 使用示例
```
# 在Claude Code中使用
"使用 Playwright Skill 为登录功能生成测试代码
- 访问 http://localhost:5173/#/pages/login/login
- 输入账号 admin@example.com
- 输入密码 admin123
- 点击登录
- 验证跳转到首页"
```

#### 结论
**可选**，适合快速生成测试代码，可与Dev Browser组合使用。

### 6. 移动端真机测试

#### 适用场景
- 真实设备验证
- 移动端特有问题排查
- 性能测试

#### 优点
- 真实设备环境
- 网络环境测试
- 用户体验验证

#### 缺点
- 需要Android设备
- 设备连接操作繁琐
- 维护成本较高

#### 环境要求
- ADB工具
- Android设备（开启USB调试）
- Chrome浏览器

#### 使用示例
```bash
# 启动ADB
adb start-server

# 查看设备
adb devices

# 端口转发
adb forward tcp:9222 localabstract:chrome_devtools_remote

# 运行测试
node tests/mobile/real-device-test.js
```

#### 结论
**推荐**，版本发布前的必做测试。

## ✅ 总结

### 推荐组合

1. **日常开发**: API测试 + Dev Browser Extension（复用登录态）
2. **功能测试**: API + Playwright/Dev Browser + uni-automator
3. **版本发布**: 全方案组合
4. **CI/CD**: Playwright + API测试（或 Dev Browser Standalone headless）

### 核心建议

1. **优先API测试** - 快速验证后端功能
2. **H5测试双选择**：
   - **Dev Browser Extension** - 日常开发、复用登录态、快速调试
   - **Playwright** - CI/CD、多浏览器、完整测试套件
3. **uni-automator做小程序** - 官方支持，适配最好
4. **真机测试做发布验证** - 真实环境最可靠

### Dev Browser 两种模式选择

| 需求 | 推荐模式 |
|------|----------|
| 复用登录态 | **Extension** |
| CI/CD 集成 | **Standalone** |
| 快速调试 | **Extension** |
| 稳定自动化 | **Standalone** |
| 企业内网/SSO | **Extension** |
