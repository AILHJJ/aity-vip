## 概述

### 目标

将 `docs/` 目录下的所有文件夹和文件名从英文改为中文,提升中文用户的阅读和使用体验。

### 背景

- 项目文档已有 200+ 页面,结构完整
- 当前使用英文命名,不便于中文用户快速理解
- 文档结构经过优化,分类清晰,适合进行中文化改造

### 范围

- **包含**: 整个 `docs/` 目录下所有子目录和文件
- **排除**: 无
- **特殊**: Git 相关文件(.gitignore 等)保持不变

---

## 设计原则

### 1. 渐进式改造

采用分批次、渐进式的方式进行重命名,确保:
- 每批次可独立验证
- 出错易回滚
- 不影响正常使用

### 2. 命名规范

#### 目录命名
- **格式**: `编号-中文名称`
- **编号**: 两位数字 (01-99)
- **名称**: 简洁明了 (2-6个字)
- **字符**: 仅使用中文、数字和连字符

#### 文件命名
- **格式**: `中文名称.md`
- **编号**: 仅系列文档使用编号
- **扩展名**: 保持 `.md`
- **术语**: 保留常用英文术语 (API, SSE, Git 等)

### 3. 编号体系

保持现有的功能分类编号体系:

| 编号范围 | 功能分类 | 说明 |

### 技术实现

#### 使用 Git MV 命令

```bash
# 重命名目录
git mv docs/01-getting-started docs/01-入门指南

# 重命名文件
git mv docs/01-入门指南/quick-start.md docs/01-入门指南/快速开始.md
```

**优势**:
- 保留 Git 历史
- 自动处理重命名检测
- 支持回滚操作

#### 链接更新策略

1. **相对路径**: 自动适应新目录结构
2. **绝对路径**: 需要手动更新
3. **文档内引用**: 使用脚本批量替换

```bash
# 示例:批量替换链接
find docs -name "*.md" -exec sed -i 's|01-getting-started|01-入门指南|g' {} +
```

## 风险控制

### 风险识别

| 风险 | 影响 | 概率 | 应对措施 |
|-----|------|------|---------|
| Git 历史丢失 | 高 | 低 | 使用 git mv,避免删除重建 |
| 链接断裂 | 中 | 中 | 批量检查和修复工具 |
| 编码问题 | 低 | 低 | UTF-8 编码统一处理 |
| 冲突文件名 | 低 | 低 | 预先检查,添加后缀区分 |
| 回滚困难 | 中 | 低 | 分批次提交,每批独立回滚 |

### 回滚策略

每批次完成后立即提交到 Git:

```bash
git add .
git commit -m "docs: 第X批文档中文化重命名"
```

如需回滚:

```bash
git revert <commit-hash>
```

### 常见问题

**Q: 为什么保留一些英文术语?**
A: API、SSE、Git 等术语是行业标准,中文化反而降低可读性。

**Q: 编号是否必要?**
A: 编号保证目录排序稳定,避免不同系统排序差异。

**Q: 如何处理已有中文文档?**
A: 保持不变,仅优化命名格式。
