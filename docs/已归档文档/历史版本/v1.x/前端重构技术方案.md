## 🎯 项目背景

### 项目概述

VIP投研内部分享系统是一个面向内部用户的私密投研分享平台，主要服务于投研团队的内部信息共享和讨论。

### 核心价值

1. **信息高效传递**：管理员可以快速向指定分组推送投研消息
2. **知识沉淀**：历史消息和讨论记录完整保存，便于查阅
3. **安全可控**：讨论内容支持可见性控制，确保信息安全
4. **灵活扩展**：支持多端访问，未来可扩展为小程序

### 目标用户

| 用户类型 | 角色 | 主要需求 |
|----------|------|----------|
| **超级管理员** | 系统管理 | 用户管理、权限控制、系统配置 |
| **管理员（博主）** | 内容管理 | 消息推送、讨论管理、用户分组 |
| **VIP用户（中线）** | 信息接收 | 查看消息、发起讨论、回复讨论 |
| **VIP用户（短线）** | 信息接收 | 查看消息、发起讨论、回复讨论 |
| **体验用户** | 信息浏览 | 查看消息、体验功能 |

## 📊 需求分析

### 功能需求

#### 1. 认证模块

**需求描述**：
- 支持邮箱和用户名双重登录
- 智能识别输入内容是邮箱还是用户名
- Token自动刷新和管理
- 记住登录状态
- 安全退出

**验收标准**：
- ✅ 输入邮箱或用户名都能正常登录
- ✅ 密码错误时提示友好
- ✅ Token过期自动刷新或提示重新登录
- ✅ 退出登录后清除本地缓存

#### 2. 消息中心

**需求描述**：
- 消息列表展示（支持分页）
- 消息详情查看
- 消息搜索（按标题、内容、标签）
- 消息筛选（按日期、分组、类型）
- 消息收藏功能
- 消息已读状态管理

**验收标准**：
- ✅ 消息列表加载流畅，支持无限滚动或分页
- ✅ 消息详情展示完整，支持富文本和图片
- ✅ 搜索功能响应快速，结果准确
- ✅ 筛选功能支持多条件组合
- ✅ 收藏功能实时同步
- ✅ 已读状态准确更新

#### 3. 消息发送（管理员）

**需求描述**：
- 富文本编辑器（支持文字、图片、链接）
- Markdown预览
- 消息标题和内容编辑
- 选择接收分组
- 标签选择（支持多选）
- 消息预览
- 发送确认

**验收标准**：
- ✅ 富文本编辑器功能完整，操作流畅
- ✅ 图片支持粘贴、拖拽、文件选择
- ✅ Markdown预览实时更新
- ✅ 表单验证完善，错误提示清晰
- ✅ 发送成功后清空表单
- ✅ 发送失败时保留内容

#### 4. 讨论功能

**需求描述**：
- 讨论列表展示
- 发起讨论（关联消息）
- 讨论详情查看
- 回复讨论
- 讨论可见性控制（公开/私密）
- 讨论搜索和筛选

**验收标准**：
- ✅ 讨论列表加载流畅
- ✅ 发起讨论时自动关联消息
- ✅ 回复功能支持富文本
- ✅ 可见性控制准确生效
- ✅ 私密讨论只对管理员和发起者可见

#### 5. 统计功能

**需求描述**：
- 消息数量趋势
- 消息类型分布
- 消息标签分布
- 用户活跃度
- 消息阅读率
- 讨论数量趋势
- 讨论回复率
- 分组用户数
- 用户增长趋势
- 支持多种时间范围统计和Excel导出

**验收标准**：
- ✅ 图表展示清晰美观
- ✅ 数据实时更新
- ✅ 支持时间范围选择
- ✅ 支持数据导出

#### 6. 用户管理（管理员）

**需求描述**：
- 用户列表展示
- 添加用户
- 编辑用户信息
- 删除用户
- 用户分组管理
- 用户权限管理
- 用户状态管理（活跃/非活跃）

**验收标准**：
- ✅ 用户列表支持搜索和筛选
- ✅ 添加用户时表单验证完善
- ✅ 编辑功能实时保存
- ✅ 删除操作需要二次确认
- ✅ 分组和权限管理准确

#### 7. 分组管理（管理员）

**需求描述**：
- 分组列表展示
- 添加分组
- 编辑分组
- 删除分组
- 分组成员管理

**验收标准**：
- ✅ 分组列表展示清晰
- ✅ 添加分组时名称唯一性验证
- ✅ 编辑功能实时保存

### 非功能需求

#### 1. 性能要求

- 首屏加载时间 < 2秒
- 页面切换响应时间 < 300ms
- 列表滚动流畅（60fps）
- 图片懒加载
- 代码分割和按需加载

#### 2. 兼容性要求

- 支持现代浏览器（Chrome、Firefox、Safari、Edge）
- 支持移动端适配（响应式设计）
- 支持小程序发布（未来扩展）

#### 3. 安全性要求

- Token安全存储
- HTTPS通信
- XSS防护
- CSRF防护
- 敏感信息加密

#### 4. 可维护性要求

- 代码结构清晰
- 组件化开发
- 统一的代码规范
- 完善的注释和文档
- 便于测试

#### 5. 可扩展性要求

- 模块化设计
- 插件化架构
- 便于添加新功能
- 支持多主题切换

## 🛠️ 技术栈选型

### 技术选型原则

1. **跨平台能力**：支持Web和小程序多端发布
2. **开发效率**：快速开发，降低学习成本
3. **生态成熟**：社区活跃，问题容易解决
4. **性能优秀**：加载快，运行流畅
5. **易于维护**：代码结构清晰，便于团队协作

### 最终技术栈

| 类别 | 技术选型 | 版本 | 选型理由 |
|------|----------|------|----------|
| **跨平台框架** | uni-app | 最新版 | 一套代码多端运行，支持Web和小程序 |
| **基础框架** | Vue.js | 3.x | 现代化、响应式强、生态完善 |
| **开发模式** | Composition API | - | 逻辑复用性强，TypeScript支持好 |
| **构建工具** | Vite | 5.x | 极速开发体验，热重载快 |
| **UI组件库** | uni-ui | 最新版 | 官方组件库，跨平台兼容 |
| **状态管理** | Pinia | 2.x | Vue 3官方推荐，轻量级 |
| **路由管理** | uni-app路由 | 内置 | 原生支持，无需额外配置 |
| **HTTP客户端** | uni.request封装 | 内置 | 跨平台兼容，统一封装 |
| **表单验证** | VeeValidate | 4.x | 功能强大，TypeScript支持 |
| **验证规则** | Yup | 1.x | 语法简洁，类型安全 |
| **富文本编辑器** | mp-html | 最新版 | 小程序兼容，功能完整 |
| **图表库** | uCharts | 最新版 | 跨平台图表库 |
| **CSS方案** | SCSS | 1.x | 原生支持，功能强大 |
| **代码规范** | ESLint | 8.x | 代码质量保证 |
| **代码格式化** | Prettier | 3.x | 统一代码风格 |
| **测试框架** | Vitest | 1.x | 与Vite集成，速度快 |

### 技术栈对比分析

#### uni-app vs 原生Vue+Vite

| 维度 | uni-app | 原生Vue+Vite | 结论 |
|------|---------|--------------|------|
| **Web端开发** | ✅ 完整支持 | ✅ 完整支持 | 平手 |
| **小程序发布** | ✅ 一键发布 | ❌ 需要重写 | uni-app胜出 |
| **开发效率** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 原生Vue略胜 |
| **学习成本** | ⭐⭐⭐ | ⭐⭐ | uni-app略胜 |
| **生态成熟度** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 原生Vue略胜 |
| **跨平台能力** | ⭐⭐⭐⭐⭐ | ⭐ | uni-app胜出 |
| **性能表现** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 原生Vue略胜 |
| **长期维护** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 原生Vue略胜 |

**最终选择：uni-app**

**理由**：
1. 满足当前Web端所有需求
2. 为未来小程序发布做好准备
3. 一套代码多端运行，降低后期开发成本
4. 技术投资回报率高
5. 风险可控，可以随时切换回纯Vue方案

const loginSchema = yup.object({

### 错误处理策略

#### 1. HTTP错误处理

**统一错误拦截**：
```javascript
// api/request.js
const request = (options) => {
  return uni.request({
    ...options,
    success: (response) => {
      if (response.statusCode === 200) {
        return response.data
      } else if (response.statusCode === 401) {
        uni.showToast({ title: '登录已过期，请重新登录', icon: 'none' })
        uni.navigateTo({ url: '/pages/auth/login' })
        return Promise.reject(new Error('Unauthorized'))
      } else if (response.statusCode === 403) {
        uni.showToast({ title: '没有权限', icon: 'none' })
        return Promise.reject(new Error('Forbidden'))
      } else if (response.statusCode === 404) {
        uni.showToast({ title: '请求的资源不存在', icon: 'none' })
        return Promise.reject(new Error('Not Found'))
      } else if (response.statusCode === 500) {
        uni.showToast({ title: '服务器错误，请稍后重试', icon: 'none' })
        return Promise.reject(new Error('Server Error'))
      } else {
        uni.showToast({ title: response.data.message || '请求失败', icon: 'none' })
        return Promise.reject(new Error(response.data.message || 'Request Failed'))
      }
    },
    fail: (error) => {
      uni.showToast({ title: '网络错误，请检查网络连接', icon: 'none' })
      return Promise.reject(error)
    }
  })
}
```
