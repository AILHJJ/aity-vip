## 三、关键发现

### ⚠️ Relay 服务器只能连接一个扩展实例

**这是导致早期测试失败的根本原因！**

dev-browser 的 relay 服务器（`localhost:9222`）设计上**只能同时接受一个浏览器扩展的连接**。

```
┌─────────────────────────────────────────────────────────────┐
│                    Relay 服务器 (9222)                       │
│                                                             │
│   ❌ 只能连接一个 Extension                                  │
│                                                             │
│   如果 Edge 已连接 → Chrome 无法正常工作                     │
│   如果 Chrome 已连接 → Edge 无法正常工作                     │
└─────────────────────────────────────────────────────────────┘
```

| 浏览器 | Extension 模式可用性 | 成功率 | 备注 |

| **Edge (系统安装)** | ✅ **可用** | 100% | 独占连接时完全正常 |

### 核心要求

**⚠️ 只能有一个浏览器连接到 relay 服务器！**

### 结论

**Edge 和 便携版 Chrome 都可以正常使用 Extension 模式！**

早期测试失败的原因是 **多浏览器同时连接**，而不是浏览器兼容性问题。

## 五、使用指南

### Extension 模式使用步骤

```bash
# 1. 关闭所有浏览器
taskkill /F /IM chrome.exe
taskkill /F /IM msedge.exe

# 2. 启动 Extension 服务器
cd C:/Users/DELL/.claude/skills/dev-browser
npm run start-extension

# 3. 只打开一个浏览器（Edge 或 Chrome，二选一）
#    - Edge: 访问 edge://extensions/ 确认扩展启用
#    - Chrome: 访问 chrome://extensions/ 确认扩展启用

# 4. 确认扩展状态
#    点击扩展图标，确认显示 "Active" 和 "Connected to relay"

# 5. 运行测试
npx tsx tmp/dev-browser-test.ts
```

### 故障排除

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `Extension request timeout` | 多个浏览器同时连接 | 关闭其他浏览器 |
| `Target not found in registry` | 连接冲突 | 只保留一个浏览器 |
| `extensionConnected: false` | 扩展未启用 | 检查扩展状态 |

## 六、与 Standalone 模式对比

| 特性 | Extension 模式 | Standalone 模式 |
|------|---------------|-----------------|
| 需要安装扩展 | ✅ 是 | ❌ 否 |
| 复用登录态 | ✅ 是 | ❌ 否 |
| 多浏览器支持 | ❌ 只能一个 | ✅ 可以多实例 |
| 稳定性 | 高（独占连接时） | 高 |
| 资源占用 | 低 (复用浏览器) | 中 (启动新浏览器) |
| 配置复杂度 | 中等 | 低 |

### 场景推荐

| 场景 | 推荐方案 |
|------|----------|
| 需要复用登录态 | **Extension 模式** |
| 自动化测试/CI/CD | **Standalone 模式** |
| 多实例并行测试 | **Standalone 模式** |
| 快速调试 | **Extension 模式** |
