# Playwright Skill 使用指南

## 1. 概述

Playwright Skill 是一个基于 Playwright 的 Claude Code 插件，用于执行浏览器自动化测试。本指南详细介绍如何使用该 Skill 为项目创建和执行测试。

## 2. 环境准备

### 2.1 系统要求
- Node.js 16.0 或更高版本
- npm 7.0 或更高版本
- 现代浏览器（Chrome、Firefox、Safari）

### 2.2 项目配置
- Playwright 已安装：`npm install -D @playwright/test`
- 项目服务器运行在：`http://localhost:5173`
- Chrome 浏览器路径：`D:\your-mcp-proxy\AITY_VIP\chrome-win64\chrome.exe`

### 2.3 Skill 安装状态
- ✅ Playwright Skill 已加载到：`c:\Users\DELL\.claude\skills\playwright-skill\`
- ✅ 依赖已安装
- ✅ 配置已完成

## 3. 使用方法

### 3.1 基本使用格式

在 Claude 对话中，使用自然语言描述测试需求：

```
帮我测试 [功能名称]，
页面地址：[URL]，
步骤：
1. [操作步骤 1]
2. [操作步骤 2]
3. [操作步骤 3]
验证：
1. [验证点 1]
2. [验证点 2]
```

### 3.2 示例场景

#### 场景 1：测试登录功能
```
帮我测试登录功能，
页面地址：http://localhost:5173/#/pages/login/login，
步骤：
1. 输入用户名 'admin'
2. 输入密码 '123456'
3. 点击登录按钮
验证：
1. 是否跳转到首页
2. 页面标题是否显示正确
```

#### 场景 2：测试行情中心
```
帮我测试行情中心页面，
页面地址：http://localhost:5173/#/pages/market/market，
验证：
1. 主要指数卡片是否显示
2. 连板天梯数据是否加载
3. 行业资金流向是否显示
```

#### 场景 3：测试讨论区
```
帮我测试讨论区功能，
页面地址：http://localhost:5173/#/pages/discussions/discussions，
步骤：
1. 点击"创建讨论"按钮
2. 输入标题"测试讨论"
3. 输入内容"这是一个测试讨论"
4. 点击发布按钮
验证：
1. 讨论是否发布成功
2. 新讨论是否显示在列表中
```

## 5. 最佳实践

### 5.1 指令编写
- **清晰明确**：使用简洁明了的语言描述测试需求
- **步骤详细**：提供具体的操作步骤和验证点
- **包含必要信息**：明确页面 URL、测试数据和预期结果
- **避免歧义**：使用精确的术语和描述

### 5.2 测试设计
- **覆盖核心功能**：优先测试核心业务功能
- **边界测试**：测试各种边界情况和异常场景
- **用户流程**：模拟真实用户的操作流程
- **性能测试**：关注页面加载速度和响应时间

### 5.3 结果分析
- **截图对比**：使用截图验证视觉效果
- **日志分析**：检查控制台是否有错误
- **性能指标**：关注加载时间和资源使用
- **用户体验**：评估操作流程的流畅性

## 6. 常见问题与解决方案

### 6.1 页面无法访问
- **原因**：项目服务器未运行
- **解决方案**：启动开发服务器 `npm run dev`

### 6.2 元素定位失败
- **原因**：页面元素选择器不正确
- **解决方案**：提供更详细的元素描述或使用其他定位方式

### 6.3 测试超时
- **原因**：网络延迟或页面加载缓慢
- **解决方案**：增加等待时间或检查网络连接

### 6.4 浏览器启动失败
- **原因**：Chrome 路径配置错误
- **解决方案**：检查 Chrome 路径是否正确

### 6.5 权限错误
- **原因**：浏览器权限不足
- **解决方案**：以管理员身份运行或调整权限设置

## 8. 团队协作

### 8.1 测试分工
- **前端开发**：负责编写和执行页面功能测试
- **后端开发**：负责 API 测试和数据验证
- **QA 人员**：负责综合测试和回归测试
- **产品经理**：负责验证功能是否符合需求

### 8.2 测试流程
1. **需求分析**：了解功能需求和测试要点
2. **测试设计**：编写测试方案和测试用例
3. **测试执行**：使用 Playwright Skill 执行测试
4. **结果分析**：分析测试结果和问题
5. **问题修复**：开发团队修复发现的问题
6. **回归测试**：验证问题是否已修复

### 8.3 文档管理
- **测试方案**：存储在 `docs/tests/` 目录
- **测试报告**：存储在 `docs/test-reports/` 目录
- **截图和日志**：存储在 `docs/test-assets/` 目录
