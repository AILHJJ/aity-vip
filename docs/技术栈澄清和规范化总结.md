## 一、问题发现

在 2026-01-29 的开发过程中，发现项目存在严重的技术栈混乱和文档不一致问题。

### 核心问题

**项目声称是 uni-app，但实际上是标准的 Vue 3 + Vite + Element Plus Web 应用。**

### 具体表现

1. **package.json 声称**：
   - 名称：`aity-uni-app`
   - 描述：`AITY VIP投研内部分享系统 - uni-app版本`
   - 构建脚本：`build:mp-weixin`, `build:mp-alipay`

2. **实际情况**：
   - 没有安装任何 `@dcloudio/*` 依赖
   - vite.config.js 使用标准 Vue 插件，不是 uni-app 插件
   - 使用 Element Plus（仅支持 Web）
   - 使用 Vue Router（uni-app 不需要）
   - **无法编译为小程序**

3. **代码混乱**：
   - 使用了 uni-app 组件语法（`<view>`, `<text>`, `<checkbox>`）
   - 但没有 uni-app 运行时支持
   - 导致浏览器控制台出现组件警告

## 四、未来建议

### 选项 A：保持 Vue 3 Web 应用（推荐）

**优点**：
- 当前代码基本可用
- Element Plus 生态成熟
- 开发效率高
- 维护成本低

**需要做的**：
1. 删除 uni-app 相关文件（manifest.json, pages.json）
2. 重构页面组件，使用标准 HTML 标签或 Element Plus 组件
3. 删除小程序相关需求
4. 更新 package.json 名称和描述

**工作量**：中等（约2-3天）

### 选项 B：真正迁移到 uni-app

**优点**：
- 可以编译为小程序
- 支持多端部署
- 符合原始需求

**需要做的**：
1. 安装所有 @dcloudio/* 依赖
2. 配置 uni-app 编译器
3. 移除 Element Plus 和 Vue Router
4. 重写所有页面和组件
5. 重新配置路由和状态管理
6. 适配小程序API

**工作量**：巨大（约2-3周，相当于重写前端）

### 选项 C：混合方案（不推荐）

保持当前状态，但添加 uni-app 支持。

**问题**：
- 技术栈更加混乱
- 维护成本极高
- 容易出错
- 不符合最佳实践

## 七、遗留问题

### 1. 前端组件警告

**问题**：浏览器控制台显示 `Failed to resolve component: checkbox`

**原因**：代码使用了 uni-app 组件，但没有 uni-app 运行时

**影响**：仅警告，不影响功能（浏览器会将其作为自定义元素处理）

**解决方案**：
- 短期：忽略警告
- 长期：重构为 Element Plus 组件

### 2. 小程序需求无法实现

**问题**：需求文档要求支持小程序，但当前无法实现

**原因**：技术栈不支持

**解决方案**：
- 选项A：删除小程序需求
- 选项B：完全重写前端（迁移到 uni-app）

### 3. 文件命名不一致

**问题**：
- package.json 名称：`aity-uni-app`
- 实际技术栈：Vue 3 + Element Plus

**解决方案**：
- 重命名为 `aity-vip-web` 或 `aity-vip-frontend`
