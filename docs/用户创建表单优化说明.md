# 用户创建表单优化说明

## 优化目标
简化创建用户表单，将邮箱字段从必填改为选填，提升用户体验。

## 选择的方案
**方案A：邮箱改为选填（推荐）**

### 选择理由
1. **数据完整性**：邮箱字段是数据库的unique索引，完全移除会导致索引失效
2. **扩展性**：保留字段便于后续添加邮箱验证、密码重置等功能
3. **兼容性**：当前登录系统支持email/username双模式登录
4. **实现简单**：只需将邮箱改为可选，后端自动生成默认邮箱

## 实施内容

### 1. 后端修改

#### 1.1 数据库模型修改
**文件**: `backend/src/models/User.js`

```javascript
// 修改前
email: {
  type: DataTypes.STRING(100),
  allowNull: false,
  unique: true
}

// 修改后

  type: DataTypes.STRING(100),
  allowNull: true,  // 改为允许NULL
  unique: true,
  comment: '邮箱地址，可选字段'
}
```

const handleSave = async () => {
  // 用户名必填，邮箱选填
  if (!userForm.value.name) {
    uni.showToast({ title: '请填写用户名', icon: 'none' })

      return
    }

### 3. 数据库迁移

**文件**: `backend/scripts/make-email-optional.sql`

执行以下SQL脚本更新数据库：

```sql
-- 移除email字段的NOT NULL约束
ALTER TABLE users MODIFY COLUMN email VARCHAR(100) NULL;

-- 为已有的NULL值设置默认邮箱（可选）
UPDATE users SET email = CONCAT(name, '@localhost') WHERE email IS NULL OR email = '';

-- 添加注释说明
ALTER TABLE users MODIFY COLUMN email VARCHAR(100) NULL COMMENT '邮箱地址，可选字段';
```

## 用户体验改进

### 优化前
- 必须填写邮箱字段
- 需要验证邮箱格式
- 创建流程较繁琐

### 优化后
- 邮箱改为选填
- 留空则自动生成默认邮箱（如：zhangsan@localhost）
- 简化创建流程，提升效率
- 仍支持填写真实邮箱以便后续功能扩展

## 功能特性

### 自动生成邮箱规则
- 格式：`{username}@localhost`
- 示例：用户名为"zhangsan"，默认邮箱为"zhangsan@localhost"
- 确保邮箱唯一性，避免冲突

### 登录方式
系统支持两种登录方式：
1. **邮箱登录**：输入 email + password
2. **用户名登录**：输入 username + password

### 后续扩展
即使现在不填写真实邮箱，保留email字段也为未来功能预留空间：
- 密码重置
- 邮件通知
- 账号激活
- 邮箱验证

## 注意事项

1. **数据库迁移**：生产环境执行前请备份数据库
2. **向后兼容**：修改后不影响已有用户数据
3. **测试验证**：确保创建、编辑、登录功能正常
4. **唯一性约束**：系统会自动检查默认邮箱是否重复
