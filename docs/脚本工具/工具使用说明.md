# 文档管理工具

本目录包含3个文档管理自动化工具脚本，用于辅助文档的索引生成、校验和归档。

## 工具列表

### 1. generate-index.js - 文档索引生成工具

扫描所有Markdown文档，提取元数据，生成多维度索引。

**功能：**
- 扫描所有Markdown文档
- 提取元数据（document_type, tags, related_docs等）
- 生成多维度索引（按类型、按模块、按标签）
- 输出JSON或Markdown格式的索引数据

**使用方式：**
```bash
# 输出到控制台（JSON格式）
node generate-index.js

# 输出到JSON文件
node generate-index.js --output ./doc-index.json

# 输出Markdown格式的索引
node generate-index.js --output index.md --format markdown
```

**输出示例（JSON）：**
```json
{
  "last_updated": "2026-03-05",
  "total_docs": 150,
  "by_type": {
    "feature": [...],
    "api": [...],
    "guide": [...]
  },
  "by_module": {
    "ai-assistant": [...],
    "market-center": [...]
  }
}
```

**支持的元数据格式：**

1. 元数据块格式：
```html
<!--
METADATA
document_type: feature
target_audience: 开发人员
status: 完成
tags: [frontend, vue, component]
related_docs: [doc1.md, doc2.md]
created_date: 2026-03-01
updated_date: 2026-03-05
version: v1.0
author: 张三
-->
```

2. 引用块格式：
```markdown
> **文档版本**: v1.0
> **完成日期**: 2026-03-05
> **设计风格**: Neon Flux
```

### 2. validate-docs.js - 文档校验工具

检查文档的完整性、结构正确性和链接有效性。

**功能：**
- 检查元数据完整性（必填字段）
- 验证文档结构（一级标题、二级标题）
- 检查链接有效性（相对路径是否存在）
- 检查图片链接有效性
- 检查代码块语法
- 生成校验报告

**使用方式：**
```bash
# 输出到控制台（彩色格式）
node validate-docs.js

# 输出到JSON文件
node validate-docs.js --output ./validation-report.json

# 输出Markdown格式的报告
node validate-docs.js --output report.md --format markdown
```

**输出示例（控制台）：**
```
=== 文档校验报告 ===

文档总数: 150
有效文档: 145
有错误的文档: 3
有警告的文档: 7
错误总数: 5
警告总数: 12

错误详情:
1. docs/feature/xxx.md
   ✗ [missing_h1] 缺少一级标题
2. docs/api/yyy.md
   ✗ [broken_link] 链接目标不存在: ../non-existent.md
```

**校验规则：**

| 检查项 | 说明 | 级别 |
|--------|------|------|
| 空文件检查 | 文件内容不能为空 | 错误 |
| 一级标题 | 必须包含一级标题（# 标题） | 错误 |
| 必填字段 | 检查title等必填元数据 | 错误 |
| 链接有效性 | 相对路径链接的目标必须存在 | 错误 |
| 图片有效性 | 图片链接的目标必须存在 | 错误 |
| 文档类型 | document_type应在标准列表中 | 警告 |
| 标题匹配 | 标题应与文件名匹配 | 警告 |
| 代码块语言 | 代码块应指定语言 | 警告 |

### 3. archive-iteration.js - 迭代归档工具

将迭代的中间文档归档到archived/iterations目录。

**功能：**
- 扫描迭代相关文档（根据tags或文件名模式）
- 生成迭代摘要（基于模板）
- 移动文档到archived/iterations/
- 更新迭代索引

**使用方式：**
```bash
# 基本用法
node archive-iteration.js --name "2026-03-market-center" --docs "market-center/实现报告.md,market-center/测试报告.md"

# 使用通配符
node archive-iteration.js --name "2026-03-ai-optimization" --docs "ai-advisor/*.md"

# 带标签和描述
node archive-iteration.js \
  --name "2026-03-refactor" \
  --docs "frontend/*.md" \
  --description "前端架构重构，使用Vue 3 + TypeScript" \
  --tags "refactor,frontend,vue3"

# 模拟运行（不实际移动文件）
node archive-iteration.js --name "2026-03-test" --docs "test/*.md" --dry-run

# 跳过生成摘要
node archive-iteration.js --name "2026-03-test" --docs "test/*.md" --skip-summary
```

**参数说明：**

| 参数 | 必填 | 说明 |
|------|------|------|
| `--name` | 是 | 迭代名称，格式：YYYY-MM-feature-name（例如：2026-03-market-center） |
| `--docs` | 是 | 要归档的文档列表，用逗号分隔，支持通配符 |
| `--description` | 否 | 迭代描述 |
| `--tags` | 否 | 迭代标签，用逗号分隔 |
| `--dry-run` | 否 | 模拟运行，不实际移动文件 |
| `--skip-summary` | 否 | 跳过生成迭代摘要 |

**生成的文件结构：**
```
docs/archived/iterations/
├── INDEX.md                           # 迭代索引（自动更新）
└── 2026-03-market-center/
    ├── README.md                      # 迭代摘要（自动生成）
    ├── 实现报告.md
    ├── 测试报告.md
    └── ...
```

**迭代摘要模板：**
生成的README.md包含：
- 迭代描述
- 标签
- 归档文档清单（表格形式）
- 文档统计（按类型、按状态）
- 迭代成果检查清单
- 备注区域

## 快速开始

### 1. 生成文档索引
```bash
node generate-index.js --output ../doc-index.json
```

### 2. 校验所有文档
```bash
node validate-docs.js --output ../validation-report.md --format markdown
```

### 3. 归档迭代文档
```bash
node archive-iteration.js \
  --name "2026-03-feature-name" \
  --docs "feature/*.md" \
  --description "功能描述" \
  --tags "tag1,tag2"
```

## 最佳实践

### 1. 定期运行校验
建议在每次提交前运行文档校验：
```bash
node validate-docs.js
```

### 2. 版本控制索引
将生成的索引文件纳入版本控制：
```bash
# 生成索引
node generate-index.js --output ../doc-index.json

# 提交到git
git add ../doc-index.json
git commit -m "docs: 更新文档索引"
```

### 3. 归档前预览
使用`--dry-run`参数预览归档操作：
```bash
node archive-iteration.js --name "2026-03-test" --docs "docs/*.md" --dry-run
```

### 4. 集成到CI/CD
可以在CI/CD流程中自动运行这些工具：
```yaml
# .github/workflows/docs.yml
- name: Validate Documentation
  run: |
    cd docs/scripts
    node validate-docs.js --output validation-report.json
    if [ $? -ne 0 ]; then
      echo "文档校验失败"
      exit 1
    fi
```

## 错误处理

所有工具都包含完整的错误处理：

1. **文件读取错误**：跳过无法读取的文件，继续处理其他文件
2. **路径错误**：提供清晰的错误信息和建议
3. **参数错误**：显示使用帮助和示例
4. **权限错误**：提示需要检查文件权限

## 常见问题

**Q: 为什么有些文档没有被索引？**
A: 检查文档是否包含元数据块，或者是否在`excludeDirs`配置中被排除。

**Q: 如何添加新的文档类型？**
A: 在`validate-docs.js`的`isValidDocumentType`函数中添加新类型。

**Q: 归档的文件可以删除吗？**
A: 归档工具是复制文件而不是移动，原文件保留。手动删除确认无误后可以删除。

**Q: 索引生成很慢怎么办？**
A: 可以在`CONFIG`中调整`excludeDirs`排除更多不需要扫描的目录。
