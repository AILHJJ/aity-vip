你提得非常准确——**智能体调度框架的演进（自研 → LangChain → LangGraph）** 确实**不应简单归入“Workflow 阶段”**，因为它属于**底层执行引擎/架构层**，而 Workflow 更偏向**任务编排的逻辑层或产品形态**。

它们的关系是：  
> **调度框架（如 LangGraph）是实现 Workflow、Agent、MCP 等上层能力的技术底座**。

因此，在汇报中，**把“智能体调度框架演进”作为一条独立主线**，与“AI应用功能演进”并行呈现，会更清晰、更体现你的技术判断力和架构能力。

---


- **主线一：AI 应用能力演进**（面向业务/用户）  
  Prompt → RAG → Agent → Workflow → MCP → Skill  

- **主线二：智能体调度框架演进**（面向系统/工程）  
  自研调度器 → LangChain Tools → LangGraph 状态化工作流引擎  

这样既能展示你对行业趋势的把握，又能突出你在**技术选型与架构升级中的主导作用**。

# 通达信AI产品落地的双轨演进路径  
**——应用能力 × 调度架构的同步升级**

作为通达信AI产品经理，我推动AI能力从实验走向生产，形成两条紧密协同的演进主线：

---

#### 一、AI 应用能力演进（面向用户价值）  
1. **Prompt 工程**：自然语言生成指标/选股条件  
2. **RAG 增强**：接入公告/研报库，确保内容可信、可溯  
3. **Agent 智能体**：支持多工具调用（行情、财务、新闻）  
4. **Workflow 编排**：实现研报生成、异动分析等多步任务  
5. **MCP + Skill 中台**：分层架构 + 标准化技能（如K线解读、指标翻译），提升复用性与可控性  

---

#### 二、智能体调度框架演进（面向系统能力｜由我主导）  
- **2024年初**：为快速验证Agent场景，**自研轻量级调度框架**，支持工具注册与简单路由  
- **2024年中**：引入 **LangChain Tools 体系**，统一接口规范，提升开发效率  
- **2025–2026年**：**主导升级至 LangGraph**，构建状态化、可回溯、支持循环与分支的**生产级智能体引擎**，为复杂Workflow与MCP架构提供坚实底座  

---

### 核心成果  
> 通过“应用能力 × 调度架构”双轮驱动，我们不仅跟上了AI发展浪潮，更**打造了适配金融投研场景的高可靠、可迭代AI执行系统**，让AI真正融入通达信产品核心。
